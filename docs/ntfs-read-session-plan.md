# 下一步建议：无需锁定用户卷的读取会话契约

2026-11-12，基于受控原始读取原型。用户已确认本方案的测试专用纯合成范围，实施由下一轮独立交付；本文不代表状态机已经实现，不改变现有后端、VHD流程或发行版本。

## 为什么先做这一项

受控VHD证明严格原始记录可读，但不能将“锁卷后读取”直接用于日常磁盘。微软说明系统卷或含分页文件的卷会锁定失败，卷上存在打开文件也会失败，并且成功锁卷会刷新缓存、让NTFS将卷视为已卸载。参考[FSCTL_LOCK_VOLUME](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_lock_volume)。因此不把锁个人卷作为快速扫描方案。

下一步建议先明确数据来自哪个时点、哪些变化必须使结果失效，再实现来源无关的分批读取与建树。否则即使合成吞吐很高，也可能将不同时间点的名称、大小和父引用混为完整结果。

## 两条路线与建议

| 路线 | 可研究的收益 | 必须解决的边界 |
| --- | --- | --- |
| VSS快照读取 | 为固定时间点提供稳定来源，避免长时间锁用户卷 | 权限、提供程序/文件系统能力、快照资源与占用、快照存活期间读取及异常清理；快照中的容量不等于当前状态 |
| 活跃卷直接读取并核验变化 | 不建立快照，可能减少初始化成本 | MFT映射迁移/增长、记录复用、目录/硬链接变化、持续写入与日志连续性；不能仅凭前后两次观察相同就声称一致 |

微软[VSS处理说明](https://learn.microsoft.com/en-us/windows/win32/vss/overview-of-processing-a-backup-under-vss)描述requester/writer/provider协调及快照生命周期。它是待验证方向，不代表本项目已拥有可用VSS读取器。微软[变化日志说明](https://learn.microsoft.com/en-us/windows/win32/fileio/change-journal-records)表明同类连续变化可能合并、旧记录可能被删除，因此“没有新增USN”不能单独证明文件一直没变。

建议本轮剩余时间只做**会话契约与纯合成状态机**，为两条路线保留来源接口；不决定将VSS设为默认依赖，不创建真实快照、不锁/读个人卷、不改系统日志或安装服务。

## 已确认的最小范围

- 将来源区分为受控静态夹具、经过独立验证的不可变来源、活跃且一致性未证明；后者即使两次映射相同、日志无新增，也不能发布“完整一致”。模拟的不可变证据不能作为真实VSS验收。
- 小型测试专用会话状态机记录批次代号、映射版本、有效长度与有限重试；发现身份/映射/引用序列或变化证据不连续时，丢弃本代已暂存结果，不混合旧批次。持续变化或修复超预算时拒绝/要求回退，取消为独立终态。
- 仅接受受限元信息输入，不实现原始读盘、完整建树或路径输出；最多4096条模拟记录和2次重启。大缓冲/队列留给后续批量读取，不为未实现能力预分配内存。
- 合成覆盖映射迁移/增长、记录复用、跨批重命名、持续写句柄、日志断档、来源失效、乱序/旧代结果、取消与重试上限；检查失败不会发布部分完整结果、未知大小不变成零、终态不被迟到结果覆盖。

## 验收与后续

交付测试专用实现、对应合成回归、取消/并发代际与边界审查、文档/记忆/迭代归档和提交。通过只证明模型遵守契约，不证明任何真实活跃卷或VSS已可靠。确认来源与生命周期后，再单独实现并验收读取适配器；真实快照、额外权限和磁盘操作需要另行具体方案与授权。
