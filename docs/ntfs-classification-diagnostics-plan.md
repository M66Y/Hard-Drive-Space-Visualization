# 有界MFT分类原因诊断方案

2026-11-12，第17轮已验证新建隔离VHD的256槽覆盖，但严格分类仍有183 invalid、6 unsupported。用户确认在本次2小时窗口剩余时间实施本方案后，已完成开发和本机受限验收，结果见[第18轮](../iterations/2026-11-12-18-mft-classification/README.md)。不直接扩大格式支持、汇总占用或把这些项当空闲。

## 建议范围

在现有测试专用枚举器及安全摘要中增加有界的“状态＋固定错误码＋数量”统计，并单独计数invalid中的全零记录。四类主分类、严格decoder、目标校验与全部读取预算保持不变；全零只是观察到的字节形态，不能自动变成空闲或已证明未分配。

固定错误码来自现有decoder代码常量，逐项白名单，不传任意消息/堆栈/路径；最多128项、所有计数之和必须等于visited。新增字段使用单独revision并严格验证；旧来源模式不改。未解析原因仍可能是当前支持不足，不能凭单一错误码断言文件系统损坏。

合成矩阵覆盖全零、非零坏签名、USA不符、未知属性、正常在用和有效空闲，检查原因与四类计数一致、未知值不丢失、关闭/失败清空及字段注入拒绝。只保留聚合计数，不增加原始记录留存、全树/名称输出或产品入口。

## 实际验证及边界

在已确认的本次2小时窗口内沿用已批准的新建256MiB隔离VHD有界范围流程，核对原因统计、21目标和清理；不扫描个人盘、不创建VSS、不改变4096槽/4MiB+bootstrap/256次预算。若窗口结束或有未解决失败，先记录半成品与授权时效，不自动延长真实操作。

完成后独立归档、更新现状/计划/记忆并提交推送；不打包发布。格式修复、MFT位图解释、更大真实样本、全卷建树与资源性能基准另行安排。
