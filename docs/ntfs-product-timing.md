# NTFS 完整主窗计时工具

## C79 可选的助手内部诊断

2026-11-28，新增测试专用入口 `DiskAtlas.Tests.exe --ntfs-personal-timing-details-ui`。仍从标准输入读取顺序和目录；只有该入口请求详细报告，普通软件和旧计时入口不采集。隔离盘包装器使用显式 `-Detailed`，可与 `-Counterbalanced` 合用。工具存在不代表已获新一轮建盘、快照或原始页读取许可。

五段耗时由助手内部的单调时钟计量：

| 字段 | 包含的工作 |
| --- | --- |
| `SourceValidation` | 所选原路径规范化、权限、固定祖先句柄及卷信息核验 |
| `VssSetup` | COM/VSS 初始化、支持检查及加入快照集 |
| `VssCreation` | 创建请求、异步等待、状态查询，以及快照属性取得、绑定检查与释放 |
| `SnapshotValidation` | 快照内祖先和所选根目录身份、属性核验 |
| `IndexFinalization` | 所有并行补查结束后，汇总大小、建立只读索引和复制范围摘要 |

前三项和快照核验不包含原路径 pins 在原 `finally` 中的释放开销。它们不是整个客户端阶段的无缝拆分，不能与已有端到端时长再次相加。索引收尾不含后续 UI 树转换。成功报告五段必须齐全；失败或取消只走原失败终态，不把未完成阶段记成零。未新增按原因的 I/O 耗时，也不能分离人工确认与系统启动。

补查按唯一对象计数，硬链接别名不重复累计。七个固定原因位为：非空驻留占用、压缩、稀疏、元信息不足、链接信息不足、修改时间冲突、严格解码不支持。一个对象可能有多个原因，用 128 个固定组合桶保留关系；各桶互斥、总和等于补查对象数。未知记录只记“不支持”，不猜文件类型。零长度且大小已知的文件不因此强制补查。原因计数指本次必须补查的对象，不是所有文件数、系统调用数或各原因耗时。

聚合报告 `ntfs-scan-details-v1` 不含路径、文件名、身份、原始页或异常文本。它在快照清理确认后经原 SID/PID 绑定管道发送，且仅在结果完整解码后交给计时端。诊断帧后若结果准备失败，保留原失败和已确认的清理状态。默认接收器拒绝该额外帧；详细接收器拒绝缺失、重复、损坏和中途插入。固定报告上限为 1,048,576 对象，实际补查仍受原扫描配置更小的容量上限约束。

详细模式增加少量计数及序列化开销，标记单独保留，不和旧模式混作无开销的性能样本。当前完成合成与本机回归，尚未用新字段做真实 VSS/卷计量，不能据此宣称已经提速。下一次实测应只用一组合成目录定位瓶颈，避免重复开展已通过的同快照正确性审计。[本轮记录](../iterations/2026-11-28-79-ntfs-detailed-timing/README.md)

## C78 权限请求到首个读取阶段

完整主窗计时从发起扫描开始，到结果查询就绪并完成同步绘制结束。C76 的计时窗口使用真实的 Windows 权限申请。软件内开启实验快扫的说明由测试入口在计时前自动确认。计时器记录客户端看到的阶段变化，可以按顺序核对以下四段。[主窗入口](../tests/NtfsProductTiming.cs#L44) · [开始和结束](../tests/NtfsProductTiming.cs#L100)

| 一段时间的起止 | 实际包含的工作 | 现有记录能回答的问题 |
| --- | --- | --- |
| 请求启动助手 → `Process.Start` 返回 | 测试入口调度启动任务，通过 Windows 的 `runas` 请求提权并取得子进程。 | 可以测得整段等待。权限窗口出现、用户确认和系统创建进程都没有独立时间戳。 |
| 启动返回 → 已核验的管道连接 | 客户端开始对助手的资源采样，等待连接并核对客户端进程身份。助手侧的进程入口、工作线程和连接前准备可与前一段重叠。 | 可以估计启动返回后等到连接的时间。该段无法单独代表整个助手初始化。 |
| 连接核验 → 客户端收到 `Snapshot` | 父进程发送所选目录，助手核对管道对端、接收请求、准备取消处理，开始报告扫描阶段。 | C76 两次均从 `Connected` 直接进入 `Snapshot`。发送请求、子进程工作和状态传回共用同一段。 |
| 客户端收到 `Snapshot` → 首个 `Reading` | 助手先核对原卷和所选目录链，随后创建 VSS 会话与快照、等待状态完成，最后核对快照中的目录身份和根元信息并释放临时目录句柄。 | 可以测得来源准备的总等待。创建快照本身的耗时尚未单列。首个原始读取句柄在发出 `Reading` 后才打开。 |

计时桥接和管道身份核验见[父进程](../src/Scanning/Ntfs/FastScanBridge.cs#L67)、[权限助手](../src/Scanning/Ntfs/FastScanBridge.cs#L207)及[计时回调](../tests/NtfsProductTiming.cs#L58)。来源准备见[阶段通知](../src/Scanning/Ntfs/NtfsPersonalScan.cs#L38)、[原卷与快照目录核验](../src/Scanning/Ntfs/NtfsPersonalSnapshotSource.cs#L64)及[VSS 会话](../src/Scanning/Ntfs/NtfsVssNativeSession.cs#L93)。

管道循环同时等待连接事件和超时检查；VSS 创建循环在等待后读取异步状态，状态完成即退出。仅凭代码中的 100 毫秒和 500 毫秒参数无法推算可节省的时间。正常权限助手在创建主窗前就分派到工作入口，产品计时也已排除主窗初始化和壁纸解码。[连接循环](../src/Scanning/Ntfs/FastScanBridge.cs#L97) · [异步状态检查](../src/Scanning/Ntfs/NtfsVssNativeSession.cs#L112) · [产品入口](../Program.cs#L9)

C76 末轮快扫比首轮多出的总时间集中在启动调用。合计其余所有阶段，末轮反而用时更短。保持其他耗时固定，分别扣除启动调用后，两次快扫仍慢于配对的普通扫描；进一步假设首个读取阶段前的全部工作都瞬间完成，则第一对快扫更短，第二对仍是普通扫描更短。这个上限包括必要的权限和来源核验，只用于判断优化空间；组内缓存和预热影响仍未单独测量。[C78 审查记录](../iterations/2026-11-28-78-ntfs-startup-audit/README.md)

## C77 大小补查耗时口径

产品主窗按收到阶段通知的时间计时。第一个对象发起大小补查时，助手发出 `Supplementing`。其余对象共用同一个阶段。所有补查工作结束后，程序还要遍历唯一对象、核对大小和链接数、计算合计并生成索引字典。索引返回才发出 `Building`，随后生成界面的文件树。因此，C76 记录的这段时间覆盖了并行查询、结果校验和索引收尾。它可以用来比较用户等待的阶段，无法换算成每次系统查询的耗时。[阶段起止](../src/Scanning/Ntfs/NtfsPersonalScan.cs#L111) · [并行补查与汇总](../src/Scanning/Ntfs/NtfsSnapshotSizeIndex.cs#L185) · [客户端计时](../tests/NtfsProductTiming.cs#L178)

## 入口与测量范围

先构建测试项目。`tests/bin/Release/net10.0-windows/DiskAtlas.Tests.exe --ntfs-personal-timing-ui`从stdin读取顺序及目录两行；目录不得放入argv、脚本正文或公开归档。原`--ntfs-personal-timing`保留旧后台口径，新入口必须单独命名；两者不能混作同一组。真实目录、VSS/raw读取和预算按本轮明确授权执行，不从工具存在推导永久权限。

新入口每条路线创建真实MainForm，采用当前默认C57/DIB配置和隔离的默认外观、不读取用户设置、不开启磁盘活动/诊断。初始化与图片解码在计时前完成，从主窗发起扫描计时：普通使用自动策略强制完整，快扫复用生产桥接与协调器核验，回退视为失败而不是合格快扫。扫描完成后等待查询就绪，完成现有失效区域的同步最终绘制后停止；没有增加第二次查询或额外Native审计。协调器通过测试注入接入MainForm，DWM实际呈现时刻与连续帧率不在测量内。

原有内存指纹在计时外比较范围、身份、两种大小、根统计和排除项，禁止将不同工作量比较发布为提速。跨时点大小不一致不等于已证明统计错误，也不能证明所有差异来自外部写入。只有一对时仍是诊断；新UI入口不会给稳定提速结论，不自动启动正式组。关闭测量窗口请求取消，等待当前任务退出后关闭；超时/清理不确定停止后续路线，不强杀助手或删除未知快照。

## 阶段与资源的准确含义

- 新增桥接观测点为LaunchStarting、LaunchReturned、Connected、ResultDecoded，仅经受测试apphost校验的ScanForTiming传入，普通生产Scan不启用。无需修改通信版本或发送额外用户数据。
- 阶段是客户端接收固定状态的区间，可聚合重复Reading等阶段。区间不重叠，嵌套bridge/publication指标另列，不相加冒充总时间。最多保留128条详细转换，超出只累计时长/丢弃计数，不使扫描失败。
- LaunchStarting至LaunchReturned包含管理员确认和系统启动，不能精确拆出人工时间。Snapshot不只是纯VSS内核耗时；Cleanup至ResultDecoded仍合并清理、传输和解码，不伪装成独立精确字段。
- 主进程与助手各250ms采样CPU累计、工作集和可取得的进程I/O；记录起止基线和采样最大值，未取得为null。助手窗口从启动返回到结果解码，不包含更早初始化/更晚退出；退出可能使最后工作集不可用。进程I/O包括管道/缓存语义，不代表物理盘吞吐；分进程峰值不能相加当成同时整机峰值。
- 普通的首个预览由100ms UI观察器记录，不代表逐帧精确时刻；快扫尚未提供完成前预览，保持null。前一路紧凑指纹会保留到比较，资源基线明确包含该影响。

## 本轮检查和诊断

`--ntfs-product-timing-tests`使用固定时钟和自有小目录，检查区间覆盖/合并/容量、白名单、借用句柄、两次真实MainForm、同步交付与原错误/清理状态传播；不访问原始卷。原`--ntfs-personal-timing-tests`与bridge/coordinator/wire检查继续保留。

C68已按当轮许可执行快扫和普通各一次，两个结果返回、快照清理确认，无回退；范围身份未观察到增删变化，但大小/占用及根统计可比检查不通过，因而按约定停止性能判定、不追加扫描。C28同快照正确性记录不因此重开。阶段表用于定位范围核验与特殊补查的成本，不能替代等工作量收益证据。

实测时暂停开发侧写盘，stdout先写到被测范围以外；结束并核对清理后才归档。实际时间、资源和比较细节仅在本机ignored artifacts中，公开只保留检查码、布尔与边界，不公开目录、文件清单、身份/指纹、原始记录或真实目录计时。完整证据见[C68](../iterations/2026-11-22-68-ntfs-product-timing/README.md)。
