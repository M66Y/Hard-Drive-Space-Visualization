## 要回答的问题

1. 用户从发起扫描到真正可用结果，NTFS快扫是否更快？

## 一次合并任务的范围

先审查已有端到端计时工具，补缺失的阶段记录，避免另造一套扫描器。若工具需修改，只改测试/诊断入口及必要的受控阶段计数；不改现有扫描调度、统计规则、背景/布局/动效、默认快扫开关或产品日志采集。

执行前确定测量目录、测试数据类型及权限边界。可以选择可保持稳定的自有合成目录，或由用户明确指定真实目录；不直接沿用旧个人卷授权，也不默认扫描整盘。若需要新隔离VHD、个人卷VSS或raw页，先给具体预算/清理边界并获得本轮许可；原始页可能包含邻近记录和驻留内容片段，不能只概括为读取目录名称。

普通路径使用自动模式的**强制完整扫描**，快扫必须真正走NTFS而非回退；目录、大小口径、呈现路径与磁盘面板状态保持一致。两条路线走现有生产协调器，并包含最终结果核验和发布，不能将后台研究核心与完整产品比较，也不能把普通刷新缓存与完整快扫比较。

## 计时与资源口径

| 记录 | 用途 |
| --- | --- |
| 发起到最终结果可用的墙钟时间 | 用户实际等待，管理员人工停顿单列，同时提供扣除人工停顿的处理时间 |
| 来源/权限助手、快照、枚举/读取、补查、索引/统计、传输、发布核验、清理 | 找主要瓶颈；嵌套阶段不能相加充当总时间 |
| 首个可用结果 | 区分更早看到内容和更早完成；不伪造快扫尚未实现的实时预览 |
| 进程工作集/CPU与可获得的进程I/O计数 | 观察代价，UI与权限助手分别注明；进程I/O不冒充真实物理盘吞吐 |
| 结果范围/两种大小/未知项/排除项及回退/清理状态的固定摘要 | 判断本次是否可以比较，不保存文件名、原始页、清单或个人路径 |

额外审计/夹具生成/预热的时间单列，不混进产品总时间，也不漏掉本来就在产品中的校验和清理。缓存、外部磁盘负载和运行顺序同时记录；未控制冷缓存则只称当前缓存条件，不宣称冷盘基准。

## 测量步骤与停止条件

1. **先一对完整扫描定位。** 普通与快扫各一次，预算建议10–15分钟。只作为诊断和可行性观察，不能据单次给出稳定加速倍数。
2. **可比且有价值时再重复。** 在用户批准的总预算内，正式组按F/O、O/F、F/O交替三对，报告各次、median与波动；前一对诊断不混入正式样本。若只批准诊断预算，先交付诊断结果和下一步建议，不自动扩展。
3. **一旦不可比就停止判定。** 范围或统计不同、检测到数据变化、发生回退/超限、取消或清理未确认时，报告具体阶段与固定原因，不追加循环扫描、不把错误伪装为提速，也不自动重开C28正确性任务。
4. **修复另按瓶颈决定。** 若来源创建/清理占主导，讨论来源生命周期；若补查占主导，分析可减少的重复查询；若UI发布占主导，检查投影和呈现。没有证据不先加并发、不放宽严格校验；较大架构变化再展示方案。
