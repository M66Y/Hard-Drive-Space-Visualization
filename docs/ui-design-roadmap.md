## 三条设计规则

### 背景：按区域决定显示程度

- 品牌与非数据留白可展示插画；统计卡、工具栏与说明文字需要稳定浅色承载；列表从表头、行到末尾空白保持连续底色。
- Treemap 图块本来较实，不统一加厚遮罩。重点改善标题说明、标签层次和选中效果；磁盘活动面板内部也不因“有背景”就推定不可读。
- 优先局部调整，不给每行文字加独立白框，不将整幅背景洗掉。默认背景与深浅不同的合成测试背景都要检查。

### 颜色：先定义含义，再选择颜色

- 品牌强调色服务主要操作与当前导航；文件类别色保留数据语义；悬停、选中、键盘焦点和错误状态各有明确表达。
- 选中不能只靠更红或更深，需结合清楚的边框／状态提示。主操作突出，次要操作保持克制，不把全部按钮画成主按钮。
- 沿用 Theme.cs 的强调色、文字色、类别色和已有自定义配色适配；只补缺失的语义样式，避免第二套竞争变量。

### 信息：默认帮助判断，详情帮助核对

- 默认突出当前目录、统计口径、空间来源、扫描状态和下一步可用操作；精确路径、硬链接及范围说明分层呈现，保留访问方式。
- 用户已选择舒适阅读，因此先调整字号与行距，接受少显示几行；窗口变小时采用合理滚动或截断，不通过把所有字缩小来硬塞。
- 第一阶段只调整信息的视觉层级，不悄悄隐藏关键状态或改变功能。信息收起、导航方式及详情展开等行为放到第二阶段评审。

## 第一阶段：视觉精修

**目标：** 保留布局和操作习惯，让默认界面在背景、文字、卡片、按钮、间距与状态上统一、舒适。

1. 核对真实主窗及现有 Theme、Wallpaper、WallpaperGrid、ChildWallpaperTable 等绘制链。对照静态截图与实际空白／滚动／状态，不把所有透明区域都判断为问题。
2. 整理有限的字号、间距、圆角与状态样式档位；优先修右侧列表完整底板、顶部和图表小字、底部详情／状态承载面。保留七项核心功能和已有窗口分区。
3. 使用同一个自建目录实际扫描，在相同背景、窗口尺寸、DPI、字体、间距、选择与扫描状态下展示两版：A 为更清爽的阅读底板；B 保留统计卡及非数据区域更明显的轻透氛围。两版列表数据底层都保持稳定，主要比较背景可见度。附现状截图作为基线，不能用静态假数据图代替程序效果。
4. 用户看实际效果后选择或提出混合取舍，再统一处理卡片小字、按钮层次、输入框／下拉框、导航与列表选中态、Treemap 标签及边框。
5. 合并完成受影响状态与使用流程检查，避免每个样式调整单独拆轮。

**主要文件：** Theme.cs、Wallpaper.cs、MainForm.cs；按实际影响调整 TreemapControl.cs、ScanProgressControl.cs。不改扫描、统计、缓存、文件定位安全判断和磁盘监测接口。

**验收：** 同尺寸真实前后对比；少行／多行／空列表的底色连续；正文和小字在不同背景下稳定可读；默认、悬停、按下、焦点、禁用、选中、扫描中、部分完成、失败与空结果可辨。采用参考文件中的项目对比度目标：普通文字 4.5:1，大字和关键控件状态 3:1，按背景合成后的显示结果检查，不仅比较裸色值。

检查当前实际最小／常用窗口，并以参考中的 1280×720、1366×768、1536×1003、1920×1080 及 125%／150% 缩放作为覆盖目标。当前代码的基准最小值为 1120×780，启动会受屏幕工作区限制；小屏下能否保持舒适字体与所有区域可用需实测，不直接宣称已支持全部目标。必要取舍先展示给用户，不擅自缩小字体或隐藏状态。记录实际环境，96 DPI 测试进程不能代替真实跨屏验证。运行项目规定的 UI 回归，背景流程被改到时才补对应背景检查，不为纯样式无关地重复扫描后端验收。

**交付：** 两版真实候选效果、用户选择、统一后的样式依据、对应检查与限制。本阶段不增加布局密度开关或可定制工作区。

## 第二阶段：交互增强

**目标：** 优先打通“看见大块占用 → 选择对象 → 了解原因 → 定位文件”的日常流程。

按以下顺序观察并改善，较大的交互改变先给具体操作示例：

1. **图表定位：** 检查点击选择、列表分页定位、父子块层次、小块提示和完整路径是否让用户明白选中了谁；保留双击进入／文件定位含义。悬停不自动变成选中，除非后续明确选择这种行为。
2. **目录上下文：** 优化当前位置、返回上级和根目录的辨识；如实际需要，再比较面包屑、前进／后退历史等新增方式，避免同时堆上全部导航控件。
3. **文件详情：** 将已有路径、修改时间、两种大小、硬链接／共享占用说明组织得更易读；不将占用宣传为删除后一定释放的空间，也不新增自动清理。
4. **搜索与状态反馈：** 提高当前搜索范围、过滤条件、清空入口和结果反馈的辨识度；统一扫描、查询、取消、部分完成、错误与空结果的提示层级。整块物理磁盘活动继续与扫描进度明确区分。

**验收：** 用固定合成目录执行上述完整任务，检查是否减少迷失、误选和不必要操作；核对键盘、快速切换、过期查询隔离、取消与旧结果恢复。仅改善真实障碍，不预先承诺没有测量的效率倍数。

## 第三阶段：高级分析与个性化

基础视觉和核心流程稳定后，从真实需求中选项实施，不把候选清单当作全部必须开发：

1. 背景显示强度、不同 Treemap 配色方案；配色需注明含义，背景变强也不能破坏核心内容阅读。
2. 紧凑／舒适布局切换；复用第一阶段已验证的舒适默认样式，再设计另一套密度及持久化。
3. 增强大文件分析，先明确现有视图回答不了的实际问题，再选择分组、筛选或比较能力；不重复实现已有 Top 文件和类型筛选。
4. 可定制工作区，只有多种工作流程的价值明确后再设计布局保存、恢复和重置，放在前三项之后。

涉及新配置、数据结构或清理能力时，仍按项目规则单独明确范围、隐私、恢复和验证。个性化不能代替默认体验质量。
