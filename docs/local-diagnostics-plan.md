# 本地诊断管理方案

状态：2026-11-07 已核查源码，待确认本轮范围；本文件不是已实现功能。基线为 `34b8b1ff5a4e45b561df5c29e67b4847f0dfb438`。

## 要解决的问题

用户遇到扫描失败、刷新降级或设置异常时，目前只能查看当前窗口及最近一份异常报告，无法在软件里查看历史、清理诊断或预览后导出。本轮建立可用的本地诊断入口，保留现有扫描和背景流程。

现有 `ErrorReport.cs` 已用字段白名单保存最近一份异常，失败不谎报成功；`RefreshStatus.cs` 和 `ScanStatistics` 已有阶段、刷新方式、计数与错误码。`MainForm.ShowIssues` 的真实路径/原始原因及 `ScanProgress.CurrentPath` 只适合当前用户本机查看，不能直接序列化到运行日志或导出。开发过程已经保存在 Git 和 `iterations/`，无需再复制一套开发日志数据库。

## 建议的三类日志

| 类别 | 含义与入口 | 默认行为 |
| --- | --- | --- |
| 运行诊断 | 软件自动生成的必要运行摘要；“诊断 → 运行诊断”查看、筛选、清空、导出 | 默认开启最小诊断，只在本地保存；可关闭，开关跨启动保留 |
| 问题记录（用户日志） | 用户主动填写的现象、复现步骤和备注；“诊断 → 问题记录”新增、修改、删除 | 不自动采集任何文本或操作；初始为空，保存前由用户主动填写 |
| 开发日志 | 开发需求、决策、变更、验证、限制与提交关联 | 继续维护 Git、`iterations/`；诊断窗口说明查看位置并提供项目版本/记录说明，不从本机开发目录或网络自动读取 |

推荐本轮完成“运行诊断 + 本地问题记录”，开发日志沿用既有归档。若希望优先交付诊断，可选择本轮只做运行诊断、暂缓问题记录；不能将暂缓说成用户日志已完成。

## 用户操作与布局

主窗口“背景设置”旁增加“诊断”按钮，保持浅色主题并随背景强调色适配。诊断为独立可调整大小的窗口，不挤占文件列表；扫描过程中可以打开。

```text
诊断                      [运行诊断开启]  本地占用 / 保留上限
[运行诊断] [问题记录] [开发记录说明]
时间 / 级别筛选    事件列表：时间、级别、阶段、结果
选中记录的可读摘要与字段
[刷新] [清空运行诊断] [预览导出…]                    [关闭]
```

运行诊断支持按时间和信息/警告/错误筛选。只有阶段变化与终态形成记录，不记录每个文件、每次鼠标移动或所有进度回调。查看和刷新在后台读取有上限的快照，关闭窗口后不再回写控件；不建立常驻服务。

“问题记录”提供标题（最多 100 字符）、现象/复现步骤/备注正文（合计最多 2,000 字符）、创建/修改时间；不自动附加文件路径、截图、背景、扫描结果或剪贴板内容。问题记录保留在本机，不纳入运行诊断导出。保存失败保留原记录，删除前明确选中项和影响。

## 采集契约与开关

- 事件限于启动/正常退出、扫描开始、阶段变化、完成/部分完成/取消/失败、实际刷新方式与降级、背景读取/导入/保存/恢复失败，以及未处理异常。信息、警告、错误的级别由固定事件映射确定。
- 允许字段：格式版本、产品/构建版本、UTC 时间、进程内临时会话/扫描序号、固定事件与结果枚举、扫描策略、阶段、刷新方式与固定原因码、并发上限/峰值、已处理文件/目录数量、跳过/占用未知数量、核验/重扫/复用数量、耗时、固定错误类别与数值错误码。未获得的数据省略，不写成已知零。
- 不记录路径、文件名、文件内容、搜索词、磁盘/账户/机器标识、原图/配置内容、原始异常文本/堆栈/附加数据；本轮也不记录扫描字节总量。明确禁止把 `ScanResult`、`ScanProgress`、`Exception` 或任意字符串字典整体序列化。
- `ScanStatistics.Reason` 和进度 `Message` 是展示文字，不成为存储/导出契约。必要时补固定刷新原因码；仅补诊断表达，保持既有扫描选择、回退与取消行为。
- 关闭运行诊断后停止接受新事件、丢弃待写事件并等待正在写入的操作结束；界面明确何时关闭生效。开关也控制最近异常报告，关闭时提示“未启用记录”，不能当成写入失败。既有记录保留，用户可另行清空；主动保存问题记录不受这个自动采集开关影响。
- 首次没有设置时采用确认后的默认值；开关保存失败不能假装已经生效，保留并显示实际状态。设置损坏时暂停自动采集，提示用户重新选择，不静默恢复开启。

## 存储、容量与失败恢复

所有数据位于软件自己的本地用户数据目录 `AsukaLens/`，不写入被扫描目录。新增结构化运行日志、问题记录和诊断偏好使用独立命名/目录，加入忽略规则；实际导出/提交仍检查内容。

| 数据 | 本轮上限与清理规则 |
| --- | --- |
| 运行诊断 | 每文件最多 1 MiB，总计最多 8 MiB，保留最近 14 天；容量或期限先达到者先清理最旧记录 |
| 最近异常 | 复用既有单份白名单报告，正常小于 512 字节；纳入查看、运行诊断开关和清理，不自动读取更早版本的临时原始异常文件 |
| 问题记录 | 最多 100 条、文件最多 1 MiB；不按时间自动删用户笔记，达到上限时明确提示整理，拒绝继续增长 |
| 待写队列 | 最多 128 条，每条编码最多 1 KiB；过量时合并/丢弃并在恢复后显示遗漏数量，不阻塞扫描线程 |

保留期限在启动、追加和打开诊断时执行；应用关闭时没有后台进程清理，旧文件可能留到下次启动。最近异常同样按 14 天清理。运行日志、设置和问题记录的临时副本要有明确所有权与清理规则，不能留下无限增长的临时文件。

日志后台顺序写入，阶段重复合并，避免 UI 线程执行文件 I/O。多实例通过短时互斥协调追加、轮转和清空，等待有上限，不能因锁竞争卡住扫描。退出尽力排空队列，有界等待；不能承诺断电或强制结束时最后几条必然落盘。

清空只处理本功能创建的诊断文件，不删除背景、问题记录、被扫描文件或用户导出文件；与写入使用同一同步规则，清空前排队的旧事件不能随后重新出现。失败时区分完全成功、部分清除与未清除，提示可重试。磁盘满、文件锁定、权限不足、损坏或超大日志均不得拖垮主功能；不递归把日志写入失败再写成日志。

## 预览与导出

流程为“筛选并勾选记录 → 预览准备导出的内容 → 选择本地保存位置”。默认不勾选记录，不自动上传或打开反馈网站。

导出从通过校验的结构化字段重新生成文本；产品/字段名称、事件与原因使用受控映射。不能复制原始日志文件，不能依赖路径正则替换来保证隐私；未知字段、枚举、异常文本和损坏记录不进入导出。若有跳过、截断或队列遗漏，要在预览中如实说明。

预览是固定快照，之后发生的新事件不自动加入；更改筛选/勾选后重新预览。最终文件必须与用户确认的预览内容一致。取消不写文件；保存失败不破坏已有目标，重试不改变所选快照；导出文件由用户自行管理，不被日志轮转删除。

问题记录属于用户主动输入的自由文本，本轮不声称能自动识别其中所有隐私信息，因此不把它拼进诊断导出。界面清楚说明这一边界。

## 实施与验收

新增模块放在 `src/Diagnostics/`，测试放在 `tests/`；按需链接测试源码，现有 UI 通过明确接口传递白名单事件。复用 `Theme` 和既有错误类别映射，将存储/导出职责从主窗分离。

1. 验证字段白名单及导出内容：注入合成私人路径、邮箱、堆栈、Data、自定义异常类型和额外 JSON 字段，确认不进入记录/预览/导出。读取旧异常文件也按既有格式白名单重新解析。
2. 用可控时钟、小配额和慢写入验证轮转/过期、单条限制、队列溢出、锁竞争、损坏/超大记录、关闭开关、退出和写失败。失败不伪装成功，内存与磁盘增长有明确边界。
3. 验证清空与后台追加竞态、失败后重试、导出预览固定快照、取消/保存失败、窗口关闭/迟到回写及多实例协调。
4. 若本轮采用问题记录，验证新增/编辑/删除/重启恢复、容量上限与原子保存；不误清除个人笔记，不混入诊断导出。
5. 验证一次扫描的完整终态、部分结果、取消、失败及强制重扫/增量降级。UI 原始路径仍仅供本机查看，七项保留功能、背景与扫描取消隔离不退化。
6. 普通应用/测试构建、核心/高级/日志回归、异常报告专项、UI 双 DPI 与新诊断专项；实际观察设置入口、筛选、清空、预览/导出和相关主题状态。按修改范围运行背景回归，不因为文档变化反复全跑。

所有自动检查与实际演示使用隔离的合成数据，不读取个人历史日志或修改个人背景。确认范围后持续完成实现、验证、说明、精简归档、清理、提交推送；本轮不正式打包。
