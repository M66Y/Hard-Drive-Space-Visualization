## 核实后的原因

- `MainForm.BuildInterface` 中标题、设置、扫描信息等连续容器使用 `WallpaperSurface.Chrome`。B 下 Chrome 为 235/255；卡片最后合成遮白程度接近它，易连成大片白块。应连同容器和占高一起调整，不能只清空文字，也不能只把全部内容变透明。
- 四个按钮分处两行；取消按钮虽不可见仍保留固定列，选择文件夹被剩余列宽拉伸；辅助操作与次操作的形态接近。尚未实测到四种不同按钮高度，不能把视觉杂乱直接说成四种实际高度。
- `ActionButton.OnPaint` 对任何 `Focused` 都加内圈，鼠标点击后焦点持续，容易与 Selected 混淆。Treemap 的 `DrawInteraction` 另有 5 DIP 浅色隔离和 2.25 DIP 强调色轮廓；截图中的两类框来源不同。
- `subtitle` 不仅是教程：它还承载部分完成、未知占用、筛选范围、快照时点和未最终预览等事实；移除顶区之前必须迁移这些语义。预览工具的合成磁盘标记和对应测试也必须迁移。

## 推荐的整体方案

1. **顶部减法：** 删除宣传标题及副说明的整个区域，回收行高；把顶部操作区分为同一行上的扫描操作和辅助操作，第二行仅放扫描策略、统计口径、NTFS 开关及必要的短状态。
2. **操作排列：** 左侧 `[选择文件夹] [重新扫描／取消]`，右侧 `[背景设置] [诊断]`。同高、固定内距、按文本合理定宽，取消与重扫共享稳定位置；只让“选择文件夹”使用暖红实底，重扫为浅暖次级按钮，背景和诊断为较轻的辅助按钮。必要时按可用宽度整组换行，不挤压字体。
3. **承载与分区：** 移除顶区和路径工具栏的大块白底，只在必要输入／文字区域保留稳定底色；KPI 仍是独立暖白卡片。用清楚的 12–16 DIP 间隔、对齐和有限圆角区分统计、路径与分析面板。列表包括空白仍保持稳定实底，不一刀切透明，不给每行小字套白框。具体透明程度依实际背景和对比检查定，不先把网页值硬套成 WinForms 最终值。
4. **注释精简：** 移走“双击逐层探索”“后台扫描不阻塞”“可随时重新扫描”等常驻教学句，已有 Tooltip／扫描详情承接解释。模块标题保持简短，数量与口径尽量并入一行。扫描阶段、取消、失败、部分完成、未知占用、过滤范围、排除目标与非实时快照必须仍有一处可见的紧凑状态，不因为精简而丢失。
5. **全局状态：** 鼠标点击普通操作按钮后不残留第二圈焦点内框；导航沿浅暖底＋短标记，树图用内部短标记和不覆盖标签的局部柔光。保持选中与悬停区别，列表与详情继续联动；键盘 Tab／Shift+Tab／空格／Enter 的焦点和激活语义保留，高对比状态使用系统色。

按钮与树图只统一状态语言，不把面积图当按钮任意缩放。树图缓存已将文字和填色合成，全块 tint 会染到文字，不能仅检查裸色便宣称可读；优先局部高光而不改大缓存架构。

## 两种状态候选

- **柔和渐亮：** 以约 140–180 ms 的填色／亮度过渡和短标记为主，鼠标按压短暂压深，不做弹性形变。
- **轻柔微弹（建议）：** 沿用上述静态识别，按钮内容做轻微压缩后自然回弹，树图只让内部高光短暂回弹，约 180–240 ms；面积、命中边界、邻居位置保持不动。参数是本项目试拟值，不是设计系统的硬性规定。

会复用已有“减弱动效”，将其覆盖按钮等新增动效；只更新当前少量活跃控件，不给每个闲置按钮常驻计时器，不每帧重建树图或遍历文件树。隐藏、禁用、取消、切换、关闭时停止并收敛到正确静态状态。

## 联网参考及取舍

- [Fluent 2 Button](https://fluent2.microsoft.design/components/web/react/core/button/usage/)：一个主操作、次级和辅助操作降低强调，简短直接的标签。
- [Fluent 2 Nav](https://fluent2.microsoft.design/components/web/react/core/nav/usage)：以持续的选中标记指示当前位置，导航内容简明。
- [Fluent 2 Motion](https://fluent2.microsoft.design/motion/)：快速自然的过渡、动效集中在相关元素，保留减弱／无动效路径。
- [Fluent 2 Elevation](https://fluent2.microsoft.design/elevation/)：层级与边界的轻量表达；不把所有控件加大阴影。
- [Google Material 3 Expressive 官方示例](https://android-developers.googleblog.com/2025/08/introducing-material-3-expressive-for-wear-os.html)：借鉴自然的弹性反馈，不照搬手表布局或会推挤邻居的形变。

保留 AsukaLens 自己的浅色角色主题，只借鉴层级、状态和动效原则；不引入大型 UI 库、不复制外部资产。网页示意可比较手感；WinForms 实现与实际性能必须另验，不能把网页动画当成桌面已实现。

围绕一个目标合并执行：`MainForm` 重排与状态迁移、`Theme`／`Wallpaper` 有限承载和按钮状态、`TreemapControl` 局部选择绘制；同步工具与测试，不改扫描后端、大小统计、权限、缓存和文件操作。
