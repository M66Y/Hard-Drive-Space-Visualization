# 滚动条拖动灰轨道修复方案

2026-11-22，基线5e07a71。用户要求修复结果列表滚动条/灰底闪动，保留现有布局、背景及动效；第三阶段实施仍未授权。

## 已核对的事实

用户提供的视频中，透明轨道在拖动期间变成完整系统灰轨道，松手后恢复。视频解码只留本机ignored artifacts，没有将其目录名称、文件清单或原始画面放入公开证据。

原有静态/反射单步消息专项29项通过，不能覆盖按住滑块时的原生内部跟踪循环。增加只观察自有合成窗口的后台采样后，真实鼠标拖动观察到2个捕获样本，其中1个轨道与原皮肤不同；步进到第70行正常。样本很少，不当作帧率或发生概率。

尝试限制位置/范围消息的原生重绘、恢复后同步补画及有界整条缓冲后，两档静态专项仍通过，但真实拖动同样2个样本中仍有1个轨道变化，尚未解决核心问题。原生指针跟踪会在普通WM_PAINT路径之外画系统样式；仅在消息返回/松手后重画不足以覆盖这个过程。首次候选的几何查询曾触发消息重入，已收窄到实际设置消息，原失败保留，不纳入通过结论。

## 建议的针对性修复

只在原来的两个滚动条上接管鼠标左键拖动、箭头和轨道点击，避免进入会画系统轨道的原生鼠标跟踪循环。保留原控件、范围/页大小/值、键盘、滚轮、UIA身份及DataGridView的现有Scroll事件；不新增覆盖窗口或替换列表，不动C57/C55和主窗绘制结构。

- 坐标使用原生几何，横向RTL反转，范围端点和页大小按有效最大值处理；不能只用16位消息高字传值。
- 使用已存在的受保护Scroll事件契约转发新位置，遵守处理器调整后的NewValue。保持系统“拖动时显示窗口内容”的既有偏好：关闭时只预览滑块，松手提交；不修改系统设置。
- 箭头/轨道按住有界自动重复，只有按下期间启用计时器；失去捕获、取消、隐藏、禁用、尺寸/句柄变化或释放时及时停止。
- 高对比与无法取得有效几何/事件桥时走原生回退。背景、滑块和箭头先在小缓冲合成，再一次发布；按条限制容量并纳入既有窗口总预算，不加全窗定时重绘。

## 验收

增加轨道几何/有效最大值/RTL/端点与大范围、拖动事件与释放/取消、重复点击/失捕获/句柄生命周期、缓冲容量/释放、两档DPI测试。用同一自有合成列表实际拖动对照，核轨道像素及列表值/滚动变化；保持被选对象和背景缓存，检查普通/C57相关UI、滚动、联动和无悬停。

检查通过后打开正常功能版，供用户体验实际搜索结果和滚动条；不以离散像素样本代替用户观感，不发布安装包。若需要扩大到新增HWND、改变滚动语义或重做列表，先另给方案。

## 实施及验收结果

已按用户批准的范围完成。第一版指针接管明显减少灰轨道，但真实复审仍发现滑块回跳；独立程序位置→原生几何反例失败，证实只禁止原生即时绘制会留下旧滑块缓存。现将原控件WM_PRINTCLIENT送入有界私有条形缓冲刷新几何，随后以完整主题画面覆盖缓冲并发布，不把系统临时像素显示到条窗口；缓冲不可用则恢复原生正确性回退。

另用不修改系统的偏好注入暴露“延迟模式先失捕获再提交”边界，改为提交ThumbPosition后释放捕获，最后EndScroll。原生范围、受处理器调整的NewValue、原条身份和背景采样关系保持。

几何修正版16组相关检查通过，用户明确接受真实操作结果；最终松手边界修正两档各42项指针、34项表面及完整UI通过，正常功能版已重新打开。完整证据与失败保留见[C63](../iterations/2026-11-22-63-scrollbar-tracking/README.md)。未扩大到新HWND、重做列表或第三阶段，没有录屏、系统改动或正式发布。

## 扩展复审更新（C64）
