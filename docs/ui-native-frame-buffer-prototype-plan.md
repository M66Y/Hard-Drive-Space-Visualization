# 原型：直接像素缓冲与更早呈现

2026-11-15，承接C47失败及本轮后续取证。用户已确认按本方案实施C48独立测试原型；普通版接入仍须实际效果复审后再决定。

实施结果：用户实际体验后反馈“明显改善，先保留这版候选”。本轮按该决定保留并重开候选，资源保护与两档DPI检查完成，不接入普通版。实现、局部收益及未关闭边界见[C48记录](../iterations/2026-11-15-48-native-frame/README.md)。下文保留原批准方案及验证目标，不代表所有目标已通过真实验收。

## 新证据与目标

用户确认原型仍有闪黑／黑边和卡顿。v3诊断保留原有32点通道，另加独立有界早期通道：纯画布12步序列中，`NcPaintEntering`和`EraseEntering`各有20个有效黑点，`EraseReturned`及后续阶段为0。此前晚阶段的0黑点漏掉了更早空档，不能作为视觉通过证明。

本组`NcPaintEntering→EraseEntering`约6–10ms，而`EraseEntering→FrameCopied`约144–237ms（首个启动组另列），说明现阶段大段时间仍在已准备画面的发布路径。该区间含取DC、复制和少量诊断，并非纯函数纳秒测量；没有DWM最终帧时间，不宣称已证明全部可见黑区的机制。

直接从GDI+ `Bitmap` 的 `Graphics.GetHdc()`读取并BitBlt的试验，全图24,576像素不一致，已撤回、移出活动编译并保留源码。不能把这类临时DC当作可靠的图片源，也不能放宽像素门槛。

静态底图与沿边柔光拆分已完成16组、40,089,600像素的全RGBA零容差比较；它只减少相同geometry/state的重复工作，每个新尺寸首次仍须绘制，不承诺缩放不重画。

## 建议实现

1. 新增一个测试专用、显式拥有的顶向下32位DIB缓冲。原型的Bitmap/Graphics包装同一块像素内存，源内存DC选中同一个DIB；发布直接复制已经绘好的相同坐标像素，不再从GDI+临时读DC猜测源图内容。
2. 统一所有权：Graphics、Bitmap包装、DIB、原生DC依次释放；部分初始化失败回收已取得资源，恢复原选中对象后删除DIB/DC。所有buffer只在UI线程使用，句柄销毁／DPI变化／关闭时失效；帧容量与静态底图合计仍限制128MiB，静态底图最多8M像素，不隐含扩大预算。
3. 只有size/DPI/state代际匹配且完整绘制成功才发布。目标DC保留其原生／托管裁切，不拉伸旧截图；遇不支持的目标变换或复制失败明确计数并保留已验证回退。普通构建不启用此路径。
4. 以已测早期阶段为依据验证呈现时机：在新客户区可用的最早消息边界尝试发布，分别观察进入、返回和后续状态。不修改窗口复制标志、系统设置或全窗合成参数，也不把调用提前几毫秒宣称必定消黑。

## 验证与停止条件

- 用合成图完整比较DIB的Bitmap视图、内存DC复制和原渲染器输出，RGB／适用alpha零容差；覆盖复杂裁切、拒绝路径、源与目标所有权及64次资源循环。
- 两档DPI核布局、背景坐标、双行列表、1.15倍柔光、输入/下拉/列表兼容；静态缓存依旧验证同key命中及失效，防止动画旧像素残留。
- 同固定序列记录实际节奏、准备与复制分段、早期及原有有效取点覆盖；不将requested30ms称实际30Hz，不把成本移出Paint当作加速。
- 自动检查和真实屏幕观察分别记录；候选展示后仍由用户判断。新原型未通过就保留证据，不自动扩大为DirectX／框架迁移或普通版替换。
