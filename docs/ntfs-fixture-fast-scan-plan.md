## 两小时目标

在新建自有256MiB隔离VHD中连通：严格record0与映射 → 有界MFT分批读取 → 有界位图前缀/已用与释放记录核验 → 有界目录索引 → 与现有目录扫描器对照。提供测试CLI运行入口和白名单结果，仍不是个人磁盘的正式快扫入口，不打包发布。开发、必要回归、真实验收、文档和提交合并收尾。

## 建议扩大范围及硬上限

- 只用本两小时内按需新建的自有256MiB VHD，创建/格式化仍走既有归属守卫，测试后立即卸载清理，不输入现有磁盘或个人目录，不创建VSS。
- 新私有固定读取profile：MFT最多4096槽/4MiB，bootstrap1024字节，加最多512字节位图对齐读取，总请求不超过4195840字节，最多256次ReadFile尝试；旧profile和形态观察模式保持原预算。只解释覆盖本次MFT槽所需的最多512字节逻辑前缀，不读取整个位图文件。
- 位图非驻留映射必须先经纯合成验证：单个未命名/无特殊flags/无扩展属性，VCN覆盖、带符号LCN、物理边界/重叠、EOF/初始化和溢出。映射元数据设置明确上限，超限Deferred或失败，不能扩大读块绕过。地址只在同owner私有状态，原始记录/位图不落盘。
- 为核验位序和在用/释放状态，允许在同自有夹具目录内额外创建并删除最多2个固定测试文件，记录仅内存的Native身份；均在锁前完成，不操作任何个人文件。锁定后核对既有21对象与这2个已释放槽，身份/状态不符即失败，不能自动修复。
- 索引最多4096记录，名称入口/字符、队列和错误表有界；保留硬链接、DOS别名、未知大小和严格分类。固定夹具目录的逻辑/实际占用与现有扫描器对照；必要的未知分配可复用经前后验证的Native元数据，但必须标明来源和开销，不把逐对象补查当纯MFT收益。
- 失败、取消、来源/映射失效或清理失败不发布完整成功结果；所有数据只在来源生命周期和本轮合成范围内使用。索引或位图状态与范围摘要分开，不能改标签把Synthetic提升为真实证明。

## 实施与实际结果

使用独立 `fixture-fast-scan` / `fixture_scanned`，旧22目标、有界v2和形态模式保留。新profile固定4195840字节/256次，旧profile不扩；映射元数据最多1MiB/128runs，仅生成首512字节对齐读取计划，完整检查后续run，不因只取前缀跳过边界/覆盖/重叠。仅解释ceil(expectedSlots/8)字节，原始页和位图不落盘。

两个witness使用CREATE_NEW及同句柄身份查询/删除标记，两个同时存在确保不同slot，目录句柄和所有文件句柄在锁前释放。释放后校验bitmap0、严格Free及同slot的新sequence=旧sequence+1；旧sequence限定1..65534，不猜溢出。依据微软[记录头SequenceNumber说明](https://learn.microsoft.com/en-us/windows/win32/devnotes/file-record-segment-header)，实际两槽核验通过。

真实473项检查完成：256槽、32字节有效前缀（对齐读取512字节），21正例及2释放槽匹配；21目录/21对象/27入口逐项与原DiskScanner一致。逻辑21233664字节、分配917504字节；7对象分配来自记录、14来自已验证Native补值，DOS别名33个排除。Range5次/263168字节，加prefix1次/512，总6次/263680，来源关闭、后验、卸载清理均通过。

本轮验收以正确性/请求量为主，没有吞吐、CPU或峰值内存基准；未测阶段耗时不作相应性能结论。两种大小仅对固定夹具目录按原扫描器口径对照，不含全部文件系统/命名流开销，不代表全卷扫描或释放空间。新路径的Windows10、大规模、活跃卷/VSS与主窗接入仍未验。
