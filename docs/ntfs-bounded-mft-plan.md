# 后续建议：自有测试卷的有界MFT分批遍历

2026-11-12，基于第16轮来源适配器；用户已另行确认本方案及本2小时窗口内的有界VHD遍历，当前尚未实现；它独立扩展了此前仅22目标的许可，不延续到以后或个人卷。

## 目的与范围

在自有固定VHD来源上走通连续读取、范围覆盖和严格分类，验证下一阶段批量读取的基础。仅遍历这次新建256MiB测试盘的MFT有效范围，不扫描个人盘、不创建VSS、不接生产入口、不保存原始记录。它比已有22目标多读系统及空闲槽，必须单独明确确认。

- native几何仍固定512字节扇区/4096字节簇/1024字节记录；Native MFT有效长度必须整记录对齐，最多4096槽（4MiB），超限在遍历前拒绝，不截取前缀后称范围完整。
- 从0到绑定的有效长度逐段读取，经已严格校验的MFT run映射寻址；每页最多64KiB，末页精确余量。私有source token/map epoch绑定同一持锁实例，关闭或取消后不继续读取，不接受任意卷/物理偏移。
- 新模式专属预算最多256次ReadFile、4MiB+1024字节（含bootstrap）；旧RawRecords和来源适配器保持2MiB/128次/22目标限制，不通过caller任意数值扩预算。
- 使用ReadInto与串行复用：一个对齐原生缓冲、一个64KiB managed页；不预取、不保留整MFT，不制造Read返回数组+拼页的第三份大缓冲。严格decoder仍有每记录私有副本，21个已知目标的解析结果可有限保留用于对照。

## 正确性与结果含义

游标覆盖不跳跃、不重叠，visited = decoded + free + unsupported + invalid。保留原严格解码；invalid/unsupported不能归为零占用或“空闲”，也不能据此断定磁盘损坏。Decoded中补查理由及逻辑/分配未知单独计数。本轮不汇总全卷占用，不把范围读完当所有格式已经支持。

固定21对象必须在同一来源读出的记录中找到，并与锁前Native及关闭后的固定核验一致；缺失、身份/名称/链接/大小不符、短读、取消或关闭失败不能报告对照通过。报告分别表达范围覆盖、四类计数、目标匹配、占用未知与source关闭/父脚本清理，不复用旧RawReport的RawRecords=22/ReadCalls最小22含义。

## 验收与停止条件

纯合成覆盖页末/EOF/跨run/负LCN/预算上限、四类状态、原生缓冲复用、取消/短读及来源失效；guard复用已有固定/无父链/nonce/镜像/分区/marker验证。新摘要深白名单与外层模式隔离、失败清空，仍不输出真实路径、引用、卷或设备身份。

如另行获准，本2小时窗口内新建隔离VHD做一次端到端范围分类与21对象对照，按需在新修正后复验；源/后置事实及清理必须完成。计数/请求字节不当物理I/O或性能保证，首轮不做WizTree倍数比较、用户盘测试或正式发布。VSS实际来源、活跃卷一致性、扩展属性/大小补查、完整建树及生产回退仍另行安排。
