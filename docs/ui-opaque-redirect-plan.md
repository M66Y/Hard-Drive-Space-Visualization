# C56：早期黑区与完全不透明整窗重定向候选

2026-11-21，用户确认C55更顺滑但仍瞬间闪黑，要求继续定点修复、保持布局/背景/动效，不录屏，先展示新的DIB候选、不设默认。

## 证据和判断

自有主窗消息跟踪发现：WM_NCCALCSIZE返回时仍是旧客户区；到第一次WM_NCPAINT进入时，新客户区已扩大，右边缘及整窗采样有黑色。该次两回调间隔约28ms，不能据此声称整个间隔都为黑色；首次DIB覆盖后取点恢复。类样式只有CS_DBLCLKS，原计算返回0，排除了CS_HREDRAW/VREDRAW及caller SWP_NOCOPYBITS。子面板跟踪的前4096条中没有黑色样本，后续2576条超容量丢弃；不能据此证明所有子控件或后半段正常。

独立WVR_REDRAW对照保留框架客户区计算，只要求整区重绘，仍有早期黑点且范围更大，拒绝接入。运行时全不透明layered对照完成，但其GDI存储表面仍可读到早期黑点；尚不能证明最终屏幕发布已消除闪黑。现阶段没有新的视觉通过结论。

## 已批准实施范围（2026-11-21）

保留现有DIB、原生控件及所有布局/背景/字体/动效，在**新的显式C56候选**中为主窗口启用Windows管理的整窗离屏重定向（WS_EX_LAYERED、LWA_ALPHA=255，无透明色键），让系统维护整窗图像后合成。完全不透明，不将软件Opacity改成99%，不使用截图遮盖、冻结拖动或系统设置调参。

这改变根窗口呈现方式，不能仅凭后台取点通过就默认启用。先补足候选开关、句柄重建和失败回退，核实alpha确为255且无点击穿透；两档像素/完整UI、下拉框、输入、滚动、动效、窗口还原和资源检查。系统重定向有额外窗口图像存储，不能谎称已计入128MiB应用像素缓存或保证不增加内存。保留C55对照，不新增框架或依赖。

通过必要检查后打开正常功能C56，人工看连续缩放是否仍闪黑；若仍有，不继续将同一策略默认化，保留失败并另给更换呈现后端的方案。用户已明确批准本候选范围；兼容性与资源检查通过后展示，仍不设为默认或发布。

依据：[Layered Windows](https://learn.microsoft.com/windows/win32/winmsg/window-features#layered-windows)、[SetLayeredWindowAttributes](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-setlayeredwindowattributes)。文档说明离屏重定向及alpha=255的不透明语义，并不保证AsukaLens实测无闪黑。
