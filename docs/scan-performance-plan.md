# 扫描性能：基线与下一步方案

日期：2026-11-07。测量时的生产基线为 `57a06f2f4c3dd030316f8bf192f263e1e3bc242e`。基线工具与方案提交为 `55b112d`；用户随后确认实施，下述首轮范围现已完成，见[实现与复测](../iterations/2026-11-07-09-high-speed-files/README.md)。以下原始测量描述优化前状态，原始合成数据见[基线归档](../iterations/2026-11-07-08-scan-performance-baseline/README.md)。

## 测量结论

当前按目录分配并发任务，每个目录内逐文件读取存储元信息。SSD 上自动与高速的目录并发上限都是 8；一个平坦目录实际只能使用 1 路目录任务。基线支持先优化大型平坦目录，但不能推导出整个磁盘都会获得相同比例的提速。

同一 SSD 上建立两组各 32,000 个合成小文件：平坦样本集中在根目录，多目录样本分为 256 个子目录。真实主窗、144 DPI、隔离且开启的诊断配置；每模式先预热，再按六种平衡顺序各运行 6 次。以下均为中位数，单位 ms：

| 样本 / 模式 | 扫描返回 | 最终列表可用 | 首个部分预览观察 | 实际目录并发峰值 |
| --- | ---: | ---: | ---: | ---: |
| 平坦 / 自动 | 1,226.31 | 1,312.94 | 659.56 | 1 |
| 平坦 / 低占用 | 2,271.07 | 2,339.06 | 644.31 | 1 |
| 平坦 / 高速 | 1,333.89 | 1,448.22 | 660.66 | 1 |
| 多目录 / 自动 | 283.53 | 348.17 | 未观察到部分预览 | 8 |
| 多目录 / 低占用 | 2,293.70 | 2,370.79 | 640.76 | 1 |
| 多目录 / 高速 | 295.57 | 359.81 | 未观察到部分预览 | 8 |

多目录的自动/高速在约 500 ms 的预览周期到来前已完成；这里没有部分预览不表示卡住。所有 36 次计时的完整扫描逐项结果与基线一致，36 次取消请求均保留此前完成的扫描对象。

单独对已经枚举的同一批文件调用现有 `NativeStorage.TryReadSnapshot`，核对每次返回的身份、大小、链接数、写句柄状态与时间戳：

| 样本 | 1 路读取 | 4 路读取 | 8 路读取 |
| --- | ---: | ---: | ---: |
| 平坦 | 981.17 | 351.33 | 188.40 |
| 多目录 | 706.00 | 236.39 | 161.33 |

这一实验不含枚举、建树、发布进度、汇总、排序和 UI，不能当作软件整体加速倍数。平坦样本从 1 路到 8 路时进程 CPU 中位数从 953.12 ms 增至 1,468.75 ms，说明并行吞吐有额外资源代价，适合先放在高速模式验证。

界面指标也已留基线。平坦高速的每次扫描最大 UI 定时器调度间隔中位数为 162.26 ms；搜索往返 334.74 ms（含现有 220 ms 防抖）；目标 75 ms 发起的取消，实际请求中位数为 100.24 ms，请求到扫描退出为 63.64 ms。它们不是屏幕帧率、真实鼠标延迟或系统级 I/O 取消保证。

另运行现有 `--policy-benchmark`：平坦 8,000 文件高速完整扫描 272.62 ms，无日志的无变化刷新 218.76 ms；多目录 7,200 文件相应为 34.75 / 39.22 ms。两组文件数不同，不能作等工作量倍数比较。核验仍逐项执行，本轮没有解除无日志刷新限制。

全部是创建后预热的元信息测试，没有清空系统缓存、控制其他应用负载、测物理 I/O 或扫描用户整盘。文件为 0–511 字节，不能代表所有文件大小、压缩状态或文件系统。工作集为 UI 定时器采样值，可能漏掉阻塞期间的峰值；总托管分配不等于保留内存。

## 已确认的首轮实施范围

用户在完成基线与方案后选择“按建议实施（推荐）”。以下为本次实施契约；基线提交本身尚未包含生产算法修改。

目标是让高速模式扫描“一个文件夹内有大量文件”时真正使用有限的文件读取并发，同时保持多目录吞吐、预览和取消能力。

1. 只在**高速模式的完整扫描**中启用大型目录内的并行元信息读取。自动和低占用保留现有行为；日志增量及元信息核验刷新继续使用既有路径。强制完整扫描适用新路径，不把所有刷新都宣称提速。
2. 所有目录共享最多 8 路原生文件元信息读取预算，避免目录并发与文件并发相乘。小目录维持简单路径；达到大目录阈值后按有限批次提交。初始实现候选为 512 文件阈值、每批 256 项，新引入的待处理文件记录全局不超过 2,048 项，最终由基准决定是否调整。
3. 不先收集整目录文件再开始读取，不创建“一文件一任务”的无限队列。等待队列和批次异步衔接，不能持有读取许可再等待下游许可，避免线程池饥饿或互相等待。
4. 延续现有原生读取、重解析点排除、未知占用标记、错误记录和硬链接汇总。取消停止入队，释放所有句柄与工作任务，旧完成结果保持可恢复；在所有任务和最终统计完成之前不显示 100%。
5. 补充实际文件读取并发的计数，与目录任务峰值区分，使扫描详情能说明高速模式是否真正利用并行。仍只记录固定类别和计数，不新增路径或文件名日志。

另一方向是同时重写三策略调度、无日志刷新核验和负载自适应。它会扩大状态与正确性验证范围，现有证据不足以证明收益，因此建议先完成上述较小范围，再决定自动模式是否采用。UI 定时器间隔仍有优化空间，本轮将其作为回归门槛，未定位前不把卡顿归因于某个绘制组件。

## 实施验收

- 正确性：逐项对比两种大小、身份/硬链接、错误及不完整状态；覆盖文件增删/替换、写入、权限失败、取消、关闭、排队上限和任务回收。核心 38、高级 25、日志 16 项回归，以及新并发边界测试必须通过；数量以实施后的实际测试为准。
- 体验：复测首预览、最终列表、取消请求/退出和搜索；生产 UI 的 144/96 DPI 回归通过，观察实际高速扫描窗口。取消恢复、最终进度及迟到回写不可退化。
- 性能：复用本轮夹具和六轮平衡顺序。平坦高速完整扫描中位数改善至少 25% 作为首轮目标，多目录扫描中位数不回退超过 10%；接近阈值或噪声较大时做一次针对性复核。目标未达则保留证据并调整或撤回优化，不仅凭原生读取实验宣告成功。
- 资源与响应：报告 CPU、总托管分配、采样工作集及 UI 调度间隔，核对新增队列的硬上限。平坦首预览和取消耗时不应明显回退；出现回退先定位，不以总扫描时间降低掩盖。高速可能增加瞬时 CPU，低占用不额外插入等待来制造区别。
- 交付：同步实际策略说明、测试、隐私检查与迭代归档，清理夹具和中间物，验证后提交并推送 `main`。普通开发构建，不打包或发布。

## 复测入口

先按项目说明构建测试项目，然后在正常 Windows 桌面运行：

```powershell
dotnet tests/bin/Release/net10.0-windows/DiskAtlas.Tests.dll --response-benchmark
```

它临时创建 64,000 个合成文件，并使用真实主窗与独立诊断配置。成功后清理夹具，报告写入 `artifacts/scan-response-results.json`；已有报告时拒绝覆盖，应先归档并移除旧报告。界面等待超时后若线程尚未退出，夹具会保留，待测试进程退出再核对清理。测试只应在可交互桌面执行。实现后报告格式 v2 仅增加文件读取与缓冲计数，计时位置、夹具、预热与轮换规则保持不变。

## 已完成：大型混合目录调度修正

以 `7e519f1` 为基线，针对高速在大型混合目录中可能慢于自动的问题，将共享预算移至目录和补充读取任务的生命周期。目录优先；只有没有排队目录、文件超过 512 且还有空闲额度时，才按最多 256 项补充并行。取消、文件身份与硬链接、未知占用、增量核验策略保持原有契约。

新增三种合成形态、每模式六轮交替完整扫描。修正后高速相对同轮自动：平坦目录耗时低约 69%，多个大型目录低约 11%，混合大小目录高约 3%；混合目录的多余托管分配基本消除。前后绝对时间受共享环境波动影响，不用它推导统一加速倍数，也不宣称高速必然最快。原始样本、资源指标和局限见[本轮归档](../iterations/2026-11-07-10-mixed-scan-scheduling/README.md)。

另提供仅对用户明确指定目录执行的四次只读完整扫描对比入口，使用真实主窗、隔离诊断和逐项结果指纹。实际目录的结果与日志留在本机，不进入仓库；本轮本机复测状态见归档中的隐私保留说明。当前预览为 `bin/Release/net10.0-windows/DiskAtlas.exe`，没有打包或正式发布。
