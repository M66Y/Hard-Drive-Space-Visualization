## 已完成：第 5 轮收尾与异常报告修复

目标是让用户能可靠地更换背景、重新打开软件后保留设置，遇到失败能理解原因并继续使用。先完成现有功能闭环，再开始新功能。背景功能延续此前确认的方向；日志管理、权限、框架迁移和发布均另立方案。框架迁移现已另行确认，见下文。

背景部分已经完成实现与验证，见[迭代记录](../iterations/2026-11-07-02-background-settings/README.md)。最小异常报告修复也已完成，见[隐私修复记录](../iterations/2026-11-07-03-error-report-privacy/README.md)。后续 .NET 10 LTS 迁移已另立方案并获用户确认。下面保留本轮范围与验收约定。

### 具体范围

1. 保留并审查现有背景实现，不从头重做。补齐应用、取消、恢复默认、重启加载、处理中关闭及源图删除后的行为。所有新测试使用隔离配置目录。
2. 补配置截断、未知版本、非法焦点、图片损坏、极端比例、EXIF 方向与保存失败检查。保存失败不破坏旧配置，错误提示说明是读取、保存还是清理失败。
3. 进度轨道与强调色同步，确保已处理/未知/终态的辨识度；背景预览展示关键文字和控件效果。核查键盘焦点、窄窗口、深浅背景与重复切换释放。保留默认明日香主题和类别统计语义。
4. 最小修复 `Program.ReportError`。用受控错误类别/代码替代原始异常全文，写入成功后才显示已保存，失败时仍能提示用户。此项不扩展成完整日志系统，也不采集用户行为。
5. 更新本轮用户说明与背景状态，记录唯一的当前预览入口，归档、清理后提交推送。旧软件、开发构建与源码状态必须区分。

### 验收场景

| 场景 | 用户可观察结果 | 验证方式 |
| --- | --- | --- |
| 选图、拖动焦点、缩放、选色并应用 | 主窗图片和组件同步变化，数据与按钮可读 | 合成横/竖/深/浅图片，真实背景弹窗流程与绘制检查 |
| 调整后取消 | 主窗和磁盘配置均保持原选择 | 前后配置比对及主窗断言 |
| 关闭再启动 | 恢复图片、裁切、焦点和强调色；源图删除后仍能恢复 | 独立进程与隔离配置目录，覆盖生产加载路径 |
| 恢复默认 | 默认背景及配色恢复，再次启动一致，原图保留 | UI 操作加重启与文件存在性检查 |
| 文件损坏或配置异常 | 明确提示或回退默认，主功能仍可使用 | 构造截断、无效值和未知版本数据 |
| 保存/清理失败 | 不丢失已保存设置，错误说明实际阶段，可重试或退出 | 受控写入失败，不修改用户系统权限 |
| 处理中重复操作/关闭 | 无失效控件回写、位图竞争或无响应状态 | 可控后台任务及相关资源生命周期检查 |
| 主题与不同窗口 | 144/96 DPI 下布局可用，按钮/进度/焦点可辨 | 两组现有回归加实际窗口观察，未覆盖 DPI 明示 |
| 异常报告 | 本地输出不含合成私人路径/原始异常文本；写失败不谎报成功 | 受控异常及存储失败注入 |
| 核心功能回归 | 七项保留功能不退化，取消/增量/两种口径正确 | 按 AGENTS 的范围表选取检查并记录结果 |

完成门槛为这些场景有明确结果、继承改动可从 Git 恢复、文档与预览入口一致。尚未覆盖的场景逐项说明，不能仅凭现有背景测试通过就关闭整轮。

## 后续顺序

当前已形成可审查的 [.NET 10 迁移方案](dotnet10-migration.md)，包含环境选择、代码范围、兼容性检查、验收和回退基线。静态核查完成，用户明确选择系统安装 SDK，现已完成安装、迁移和全部自动回归，见[验收记录](../iterations/2026-11-07-05-dotnet10-migration/README.md)。下一项为本地诊断管理，需先明确三类日志与保留策略，不在本轮顺带实施。

| 顺序 | 建议方向 | 开始前需要明确 | 验收重点 |
| --- | --- | --- | --- |
| 已完成 | .NET 10 LTS 迁移 | 支持的 Windows 版本、开发 SDK、运行依赖与回退基线 | 核心/日志/UI 全部回归、启动与背景兼容；按用户选择系统安装 SDK，保留 .NET 9 |
| 2 | 本地诊断管理 | 三类日志的含义、入口、默认开关、字段与保留策略 | 脱敏、容量/期限、查看清理、导出预览、写失败隔离；无默认上传 |
| 3 | 扫描策略与响应优化 | 同条件数据和实际瓶颈，是否确需单目录并行 | 逐项结果一致、取消隔离、首预览/操作响应和资源数据，不只总耗时 |
| 4 | 界面信息与可维护性 | 具体用户问题及组件草图，状态职责划分 | 明确口径/范围/不完整状态、键盘可用，按修改边界抽取主窗职责 |
| 发布前 | 用户文档与交付 | 中英文结构、资源许可、正式版本范围、安装方案 | 干净源码可构建，便携/安装/源码四类资产实测，Release 快照与校验完整 |

不为日志不可用场景直接采用“跳过核验”的近似缓存。若后续确需持久扫描缓存或监听器，单独设计连续性证据、失效及退出/重启语义，再讨论收益与成本。

目录迁移与自动化构建检查可在接触相关模块时逐步实施，先修容易用错的启动入口和状态说明，不把全仓重排作为下一轮的前置条件。
