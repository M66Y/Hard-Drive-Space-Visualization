### NTFS-01：统计语义与补查

输出每类记录的支持范围、大小来源和补查原因；明确驻留数据、普通非驻留、压缩/稀疏、命名流和目录元数据的边界。逻辑大小按入口累计，实际占用按对象去重；范围外硬链接、DOS 名称和共享对象的归属不能混算。未知值保留未知计数，不伪装为零或删除后可释放空间。

分轮验证属性列表和扩展记录拼接、记录引用序列、碎片化与损坏输入。补查器必须有并发、队列、容量和取消边界，不支持的格式回退或明确部分完成。受控夹具上逐项对照现有 NativeStorage，分别记录直接解析和补查的数量/耗时；若常见文件需要大量逐个补查且抵消收益，先修订路线再进入整卷实现。

验收以两种大小、入口/对象关系、未知与错误状态一致为主，不以速度掩盖统计缺失。新 VHD、其他系统/几何的实际操作先按本轮范围明确授权，不沿用上轮一次性提权许可。

压缩/稀疏默认流补查的前置核查已完成：`NativeStorage` 改为使用句柄属性选择查询，7 类临时 NTFS 文件的 28 种提示在变更前后都未见大小差异，属于防御性改进，见[属性记录](../iterations/2026-11-12-08-storage-attributes/README.md)。本小时用户已确认继续开发独立原型，以句柄实测属性、完整身份、EOF、可见链接数、修改/变化时间及两组 CompressionInfo 验证大小。只接受单一 `Compressed` 或单一 `Sparse` 理由，叠加命名流、属性列表、扩展、加密、重解析等继续未知；理由组合应以真实夹具结果确定，不能通过掩掉标记扩大支持。

本轮已完成四类静态合成文件的补查对照、已有写者/删除者拒绝、取消与资源释放检查；实际组内属性竞争和活跃卷仍未验收。接口输出只代表所开流，不包含所有命名流、整个文件系统开销或删除释放量。参考 [FILE_COMPRESSION_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_compression_info)、[流与分享](https://learn.microsoft.com/en-us/windows/win32/fileio/file-streams)、[稀疏操作](https://learn.microsoft.com/en-us/windows/win32/fileio/sparse-file-operations)。原型不进入整卷 MFT 或生产后端；本小时的重复 VHD 授权不延续到以后。

下一轮先研究 **NTFS-01-KERNEL-USA**：额外硬链接或较长命名流夹具中，IOCTL 返回的两个扇区尾字仅一个匹配 USA 保存值，当前严格入口拒绝。刷新本轮文件及命名流未消除失败，根因尚未证明；不能据此称磁盘损坏，也不能将未校验尾字直接放行。用户已选择本轮保持严格校验，先完成受限形态。后续需给出可核验的读取表示与恢复策略、独立依据及损坏输入回归后，再扩大支持；命名流/属性扩展补查、活跃卷协调及 NTFS-02 继续未完成。失败与成功样本分别归档，不合并为全范围通过。

用户已确认按[内核记录验证方案](ntfs-kernel-record-plan.md)推进：留样基础后，固定21对象/63请求矩阵、Live/IOCTL绑定与真实VHD留样均已完成本轮验收，见[矩阵记录](../iterations/2026-11-12-13-kernel-matrix/README.md)。两次矩阵均36解码/27严格失败，6条最终原始失败记录独立重放匹配；下一步应基于这些证据研究内核表示与读取策略，另给修改解码/替代读取方案。不将“收集完成”当作“失败已修复”，其他系统、实际并发及整卷MFT仍未验收。本轮VHD授权不延续到以后。

### MON-01：主界面磁盘活动面板

用户已确认进度条上方的实际窗口布局。首版已实现下述主要交互、真实本机单盘采样及合成状态检查；详细实现与尚未验收项见[磁盘活动说明](disk-activity.md)。以下保留完整目标，不能将首版通过等同所有系统和设备已通过。

建议位置为扫描进度条上方的可折叠小面板，先提供实际尺寸效果供用户确定。显示最近 60 秒活动曲线及活动时间、读取速度、写入速度和平均响应时间；颜色适配主题，窄窗口保留简洁摘要，展开时不遮挡图表、文件列表或取消按钮。

默认跟随扫描目录所在的物理磁盘，可手动切换；C/D 等分区若同属一块磁盘，明确显示同一物理盘指标。首版优先支持可可靠映射的本地单磁盘；跨盘卷、网络、虚拟盘和未知映射不猜测。显示“整块磁盘，包含其他进程”，不能当作 AsukaLens 的专属 I/O，也不能把元信息处理量或估算进度当作磁盘速度。

每秒后台采样、仅内存保存最近 60 点；最小化、关闭面板或关闭窗口时暂停/释放，恢复后缺口与首样本等待应可见。计数器失败、设备消失、待首个有效间隔时显示不可用/等待，而不是假 0。不新增后台服务、默认日志留存或自动上传，不为读不到指标默认提权。

验证中文/英文系统计数器适配、多磁盘映射与盘切换、休眠恢复、设备拔出、采样异常/过期结果、144/96 DPI、最小窗口和主题对比。与任务管理器做同一物理盘、近似同时段的趋势核查，保留采样口径差异；测量面板开启/关闭对 CPU、内存和扫描的影响后再设门槛，不能凭 1 Hz 推断“零开销”。

### NTFS-02：批量读取与真实资源评估

先研究如何安全批量读取并验证 MFT 的数据流与碎片布局；逐目标 `FSCTL_GET_NTFS_FILE_RECORD` 的 140 项验证不是批量扫描实现。按记录 ID/父 ID 建立紧凑索引，限制缓冲与队列，避免先为整卷每个节点复制完整路径。验证挂载点、重解析点、扩展记录、引用复用和取消；活跃卷须设计变化核验与有界修复，不能把一遍批量读取视为原子快照。

分别计量读取、解析、索引/建树、汇总、补查及 UI 展示成本，主比较使用端到端完成时间，另记录首个预览、搜索/切换和取消响应。基准在相同统计口径、范围与权限下，区分完整扫描和刷新、冷暖缓存及外部负载，交替多次运行并报告中位数和波动。记录进程 CPU、实际峰值工作集/托管内存和可取得的磁盘指标；总分配量不充当峰值内存，整盘负载不充当进程 I/O。

对照现有扫描器；若另比 WizTree，记录其版本、权限和统计范围，解释受保护目录及系统元数据差异。先用受控 NTFS 夹具，真实目录/整盘必须由用户指定；原始路径、文件清单和本机报告不公开。性能目标在基线完成后确定，不预先承诺秒数或倍数。若收益不足，保留正确性结果并重新评估，不能仅为“高速”名义强行接入。

### NTFS-03：产品接入与回退

收益成立后再确认短生命周期提权助手、主窗入口与扫描后端选择。主界面保持普通权限；用户主动选择 NTFS 快速扫描时才进入权限流程。拒绝授权、非 NTFS、无法读取、未知格式等须回退现有扫描并说明原因。

整体验收覆盖七项功能、两种大小、搜索排序与定位、首个预览、阶段、取消、关闭、旧结果恢复和连续扫描。后端切换必须丢弃本轮未完成索引，不混合不同批次；不修改系统日志配置作为隐藏前提。Windows 10/11 与未知边界的实测分别记录，未验证项目不宣称支持通过。

### APP-01：软件占用分析

新增“选择软件”的只读入口，候选来源为安装信息、快捷方式和用户选择的 EXE；首版先选少量典型软件，避免承诺自动识别所有桌面、商店和便携软件。关联安装目录、用户数据、日志和缓存位置，在同一视图查看体积、大文件及两种大小。

每个关联位置展示依据与“已确认/疑似/用户补充”等状态；共享组件和多软件共用目录单独说明，跨软件汇总不得重复相加。不能按名称相似就归属，更不能把识别到的部分目录称为全部占用。不执行或跟随不可信卸载命令，不启动待分析 EXE 来识别软件。复用现有图表和查询，但限定扫描范围，避免为了找一个软件默认扫描整盘或其他账户。

验收包括安装位置缺失/失效、多个版本、卸载残留、共享目录、便携软件、自定义路径与权限不足；确认取消和错误不会影响原文件夹扫描。模型完成后再谈软件关联规则的覆盖率与维护成本。

### APP-02 / CLEAN-01：先建议，后受控清理

APP-02 为已验证的软件/版本维护少量规则，说明候选类别、关联证据、用途及适用条件。目录名包含 Cache、文件很旧或很大，都不能单独证明冗余；用户作品、配置、凭据、下载和共享数据需区分。对未知软件保持只读查看，优先提供定位或软件自身清理入口。候选字节数也不直接等于可释放空间。

CLEAN-01 仅在用户明确确认后另立设计：逐项预览并选择，检查软件运行状态，重新验证路径和归属，拒绝重解析点越界，处理部分失败和恢复。回收站/隔离区并非所有磁盘和文件都支持；恢复策略不明时不能退化为静默永久删除。清理后重新扫描核对，遵守实际占用与硬链接口径。初版不做默认自动清理、注册表清理或卸载功能。
