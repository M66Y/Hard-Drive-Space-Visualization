# 列表滚动背景割裂修复

2026-11-14，承接第一阶段未收尾工作区，基线 `9ac1f0b`。本轮只修列表滚动，不重启已暂缓的最小化闪黑研究，不改变用户已确认的1.15倍沿边柔光。

## 已核实的问题

`WallpaperGrid`并非真正的透明图层：空白区和每个单元格都调用`Wallpaper.Paint`，取窗口同位置壁纸、叠加浅色底，再画文字。DataGridView原生`ScrollRows`先调用`ScrollWindow`搬移已画像素，之后才触发`OnScroll`。当前`Invalidate`仅排队补画，可能出现背景先随行搬移、随后跳回的瞬间。

旧滚动专项只在50毫秒后检查最终WM_PAINT覆盖范围及数据状态，不能证明滚动过程没有旧像素搬移，也没有检查每单元格重复背景合成的成本。最终画面正确不等于动态过程通过。

框架依据：[.NET 10 DataGridView滚动源码](https://github.com/dotnet/winforms/blob/v10.0.0/src/System.Windows.Forms/System/Windows/Forms/Controls/DataGridView/DataGridView.Methods.cs)、[ScrollWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-scrollwindow)。

## 建议范围

保留背景明显、当前透明程度、圆角和原生列表输入/键盘/排序/选择/可访问性。给列表建立有容量限制的固定底图缓存，只有图片、裁切、窗口与模块位置/尺寸、DPI、主题或保护透明度变化才重建；滚动和选中不重新合成壁纸。每帧复用固定底图，仅绘制可见行的文字和选中覆盖。

滚动须在同一次操作内完成新视口绘制，不能继续只排队事后补画。先核对原生滚轮、滚动条、键盘及程序定位的入口；如需要局部暂停像素搬移，只作用于列表自己的短同步操作，严格配对恢复，不使隐藏窗口意外显示，不调用DoEvents，不刷新整个主窗口。

另一方向是改用纯浅色列表底板，彻底取消列表对壁纸的取样；它会改变背景透出的设计，因此不默认采用。

## 验收

- 用自建合成目录和高辨识度合成背景，覆盖上下快速滚轮、滚动条拖动、横向滚动、键盘翻页和图表定位；实际窗口由用户复审。
- 默认144和96 DPI核对固定背景、文字/选择/行身份、未滚动邻区和不同背景更新后的失效；缓存有上限、隐藏和释放时清理。
- 记录同一夹具的绘制次数、背景合成次数和本机耗时，区分最终像素、过程机制与人工体验，不把微测试当物理帧率或普遍加速保证。
- 运行应用/测试构建、滚动专项、受影响表面和完整UI流程；通过后更新状态及记录，阶段整体收尾仍等用户反馈。
