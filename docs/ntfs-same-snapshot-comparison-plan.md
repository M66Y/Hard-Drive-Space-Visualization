# 同快照逐项对照方案

2026-11-13，代码基线 `420a054`。用户已确定先完成 NTFS 对照，再按保留角色背景、暖红浅色与稳定数据底板的方向优化界面。用户已确认按本方案实施并允许本轮同快照操作；截至方案确认时尚未执行，具体完成与清理以验收记录为准。许可仅限本轮。

## 问题与交付目标

C27 已修复生产助手的启动线程问题并通过真实界面验收。完整后台 F/O 的目录入口、身份及排除范围一致，但文件逻辑大小和原始分配量存在差异，且差异项中有修改时间晚于快照的对象；不能由此断言全部来自外部变化，也不能宣布等工作量提速。

本轮在同一份只读快照上运行现有 NTFS 后端与原目录扫描器，逐项核对并分类。相同来源仍不一致时定位具体统计分支；一致时只说明本次同源检查通过，不反推 C27 差异全部已解释。不新增产品选项、发布版本或开始界面改版。

## 实现范围

1. 复用 `NtfsPersonalScan.Run` 的清理前验收回调及其自持 `NtfsPersonalSnapshotSource`，不允许传入任意现存快照。测试入口沿用同应用身份/进程启动时刻/本机管道对端校验；目录从 stdin 经受限私有管道进入助手，不进入 argv 或文件。测试摘要仅在快照清理结果明确后发送。
2. 原目录扫描直接读取该 owner 的 `SnapshotDataRoot`，使用固定八路测试配置，不经过会打开实时变化日志的 `ScanCoordinator`。不用快照设备路径的自动设备探测代替日常自动模式。保持原扫描器的元信息读取、两种大小与硬链接处理，避免把两路替换为同一实现后假称独立对照。
3. 为测试扫描提供内部有界入口核验：最多 1,048,576 个发现入口，名称和目录相对路径分别最多 64 Mi UTF-16 字符；排队目录与总入口共享硬上限。超限终止，不能被普通逐项错误捕获后变成部分成功。取消等待所有扫描任务结束再清理来源，原产品未启用此测试配置时行为保持不变。
4. 逐项按相对路径哈希对齐，分别核类型、完整身份、文件逻辑大小、对象原始分配量、链接数和未知状态；目录只核身份/类型。按入口汇总逻辑大小、按对象去重汇总占用，单独核根统计及排除集合；不把硬链接的逐入口归账位置或目录元信息大小误判为文件统计差异。最多保留两份有界比较信息，不保存原始清单或副本。
5. 有差异时在同一来源补查最多 1,024 个差异对象，默认串行。区分普通查询与快照查询分支，并观察句柄 EOF、分配量及普通/压缩/稀疏属性；实际大小和标识仍只在内存。超出诊断上限、补查失败或来源清理未知必须明确标为未完成，不能据部分补查宣布全部差异解释完毕。驻留性不能仅凭属性或大小猜测。

## 本轮拟用真实边界

- 仅用户此前指定并在本轮再次确认的个人目录；不访问其他范围或链接目标，不新建 VHD。
- 只创建本次一个 VSS 快照，顺序完成快扫、普通扫描与有界差异补查后清理；不修改差异区配置，不删除其他快照。
- 沿用 Large 原始读取上限：1 GiB＋2 MiB、65,536 请求、每次最多 64 KiB；其他既有 MFT/位图/补查预算不扩大。原始页可能含邻近记录和驻留内容片段，仅读取需要的元信息，不调用文件正文读取 API，不保存或上传原始页。普通对照保留原扫描器的句柄访问标志（包含读取标志），句柄只用于元信息查询；不因改权限而更换被比较的查询路径。
- 同快照普通扫描最多 1,048,576 个入口；上述 1,024 个差异对象补查为额外诊断预算，不混入快扫原有 Native 补查额度。
- 整个读取任务使用 10 分钟取消上限，通信总期限 12 分钟；快照将比 C27 的快扫单独执行保留更久。超时停止，不自动重扫或转向实时目录；取消、所有任务退出和本次快照清理分别检查。
- 仅输出固定阶段、类别、相等性及完整性布尔值；个人路径、对象身份、哈希、数量、大小、清单不进仓库。新来源操作的许可仅限本轮，不成为未来默认许可。

## 验证与收尾

先做纯合成的相等、大小/身份/未知/硬链接差异、排除边界、预算、取消和异常净化测试，再运行原扫描器相关核心/高级及通信检查。真实操作前确认新的边界；实际失败立即反馈，不静默追加扫描。结果清楚区分同源对照、差异补查与清理是否完成。

本轮不是产品端到端速度基准：共用快照、固定并发和额外对照均改变测量条件。先解决正确性，后续性能结论另按实际产品链路验证。实现、结果、限制、项目状态、记忆与可恢复补丁统一归档；检查通过后按既有授权提交并推送 main，不打包发布。

界面优化排在本轮之后，首轮建议仅处理列表整块底色、小字承载和组件一致性，使用真实程序扫描自建测试目录做同尺寸前后对比。外部建议中的角色设定与执行命令不替代项目约束和用户确认。
