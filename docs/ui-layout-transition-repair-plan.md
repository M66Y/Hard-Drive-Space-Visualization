原生锁不是单纯暂停画笔：[WM_SETREDRAW](https://learn.microsoft.com/en-us/windows/win32/gdi/wm-setredraw)会影响WS_VISIBLE，[IsWindowVisible](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-iswindowvisible)又检查祖先链；[.NET10官方源码](https://raw.githubusercontent.com/dotnet/winforms/v10.0.0/src/System.Windows.Forms/System/Windows/Forms/Control.cs)在SetRegionInternal中用这个结果决定SetWindowRgn是否请求重绘。因此存在可验证的锁/裁切耦合，但不是此次全部故障的已证实根因。WallpaperTable.OnSizeChanged在base之后仍写Region，OnLayout结束也不普遍等于最后一次裁切完成。

## 已核实与尚未证明

- `MainForm.UpdateScopeLayout`按说明文本将行高从0改为至少28 DIP，必要时按长警告继续增高。重扫开始会显示旧结果提示，预览/最终/取消/筛选也可能改变这行；底部操作行、分页行另有动态高度。固定一行高度不能覆盖长警告的全部情况。
- `MainForm.OnResize`先调用`Invalidate(true)`再执行范围测高。`WallpaperTable.OnLocationChanged`也仅在基类处理后调用`Invalidate(true)`，没有统一的“最终布局/最终裁切/受影响旧区域及后代呈现”边界。这是值得验证的时序缺口，不单独证明原生像素搬移就是唯一根因。
- 壁纸已共享整窗栅格缓存。各表面按窗口偏移采样该缓存，但`Wallpaper.Paint`会先铺实底，再画壁纸和浅色wash，不应把原因直接描述为半透明层盖不住旧像素。
- `UpdateContentClips`已经在Layout/Size/DPI变化后计算圆角交集，键含子控件Bounds；目前不能直接认定最终Region仍旧。仍需检查一次操作中的中间裁切和旧区域暴露顺序。
- 列表底图键含祖先累计位置/窗体尺寸，下一次Paint不会错误复用旧位置的缓存；祖先移动后何时真正Paint是另一问题，不能用缓存键正确代替及时显示的证明。
- 现有`BackdropStabilityTests`检查几何、文字变更、栅格引用和Region次数，并主动布局/等待；表面检查还会Refresh/DrawToBitmap。这些不能排除已显示画面上的短暂残影，先前通过不等于该新场景已修复。

微软文档明确指出[Invalidate不会强制同步绘制](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.control.invalidate?view=windowsdesktop-10.0)，[Update只处理已失效区域](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.control.update?view=windowsdesktop-10.0)。这些是API语义证据，不是本软件根因或某个修法有效的证据。

## 推荐范围：先保持当前布局和背景表现

1. 用自有合成目录/受控ScanGate固定“完整结果→开始重扫→首预览→完成/取消恢复”的时点；暂停后续预览更新，检查是否仍要等下一次约500ms预览才能补画。补充partial/恢复、长范围说明、分页和连续缩放对照，不访问个人目录、VSS或计数器。
2. 优先从确实改变几何的范围行与底部操作行入手，合并同一操作中的布局变化；记录分析区等受影响容器的旧/新位置，在最终布局和裁切稳定后，对暴露区域及受影响子树进行一次受控呈现。若需要排队补画，合并为一个待处理请求，避免每个子控件移动都立刻重画中间布局。
3. 连续缩放检查祖先位置、栅格代际和最终裁切；复用有边界的合并机制，避免每次计数/预览或每个子控件都同步刷新全窗。不默认增加永久留白、遮挡数据的浮层或拖动时纯色背景，不引入WS_EX_COMPOSITED。
4. 先保留未修版本的可复现反例，再以同一序列验证。若时序修复不能解决，由证据决定是否另外选择固定范围区或其他视觉取舍，不把多种候选一次性叠入产品。
