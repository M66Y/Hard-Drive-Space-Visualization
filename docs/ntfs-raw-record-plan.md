# 受控原始 NTFS 记录读取：本轮方案

2026-11-12，基线 `fa21d9e57d225f263f59d4a7f4230e520381097b`。用户已确认以下方案及本轮按需重复隔离VHD验证，现已完成受限原型和三次真实对照（含最终代码）；实际结果与失败尝试见[迭代记录](../iterations/2026-11-12-14-raw-records/README.md)。原有raw/kernel严格入口、生产扫描器与发行包不变。

## 调查结论与选择

上一轮6条本机样本均重新核验正文长度/哈希与清单。仅作有界结构观察时，第一扇区尾字位于非驻留DATA头的属性编号；用USA保存值机械覆盖会与另一属性编号冲突。这些记录没有通过USA，因此该观察不能视为成功解码或根因证明，也不构成放宽入口的理由。

微软的[记录IOCTL](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_ntfs_file_record)没有约定USA返回表示或快照。[USA机制](https://learn.microsoft.com/en-us/windows/win32/devnotes/multi-sector-header)描述的是写盘保护与读回恢复。继续忽略不匹配尾字的逻辑入口证明负担较高；离线VHD容器解析还会增加文件格式解析范围。

建议先做**新建隔离VHD内的有限槽位原始读取**，保留当前严格解码器。先纯合成验证MFT映射，再在同一个自有测试卷内采集Native基准/IOCTL观察、关闭文件句柄、成功锁定该虚拟卷，通过持锁句柄只读原始记录，解锁后复核对象。没有任意卷/磁盘号/偏移输入，不锁宿主C/D盘。

官方说明[锁卷成功会先刷新缓存且卷上没有打开文件，NTFS视其为已卸载](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_lock_volume)。锁失败即停止；不用强制卸载绕过，也不把此流程推广为生产活跃卷快照。锁会在显式解锁、关闭句柄或进程退出时释放。

## 最小实现范围

1. 新增纯内存MFT映射模块。原始record0必须先经现有 `Decode` 完整校验；只接受基记录中一个普通、未命名、非驻留DATA。完整验证runlist、VCN连续性、LCN有符号增量、分配/逻辑/初始化长度、几何与卷边界，拒绝稀疏、压缩、属性列表、扩展及不完整覆盖。最多128个区段，不假定MFT连续。
2. 槽位寻址按经校验的映射拆分读取，核对乘加溢出、MFT有效长度与记录边界，支持受控的跨区段组合。record0只用经核对的卷几何定位；不能将 `MftStartLcn + slot × recordSize` 当通用公式。[MFT的未命名DATA是按顺序排列的记录流](https://learn.microsoft.com/en-us/windows/win32/devnotes/master-file-table)，它也可能依赖属性扩展，首版明确拒绝。
3. 新增测试专用的有限原始读取器，复用既有VHD/nonce/物理extents/分区/卷marker守卫。首版真实几何限定NTFS3.1、512字节扇区、4096字节簇、1024字节记录；只读record0及既有固定矩阵的21个已知对象，不枚举整卷。
4. 锁前采集完整身份、EOF、分配量、可见链接与受控名称上下文并关闭全部文件句柄；成功锁卷后通过同一卷句柄读，原始偏移以卷为起点，不再叠加宿主分区偏移。读缓冲/长度/偏移满足[直接I/O对齐要求](https://learn.microsoft.com/en-us/windows/win32/fileio/file-buffering)。仅请求读访问，不新增WriteFile或磁盘写方法。
5. 原始记录只走严格 `Decode`；对照完整引用、默认EOF、可见链接/名称关系及已知直接分配量，未知分配继续未知。解锁后重新读取Native上下文，任何变化、解锁或清理失败均不能算完整验收；映射不跨解锁复用。

不使用卷句柄的 `FSCTL_GET_RETRIEVAL_POINTERS` 获取所谓MFT映射：[卷句柄用法返回坏簇位置](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_retrieval_pointers)，文件区段映射需要对应文件句柄。本轮选择从严格record0解析受限映射。

## 预算、验证与证据

- 每次仍新建256MiB自有VHD。上层固定record0及21对象共22条（小于32条方案上限），底层最多128次ReadFile尝试、每次64KiB、累计2MiB；区段/缓冲/目标数量均有边界。子进程2分钟、日志1MiB。锁定后不运行UI或访问路径，不持锁等待用户操作。
- 纯合成覆盖多区段、跨区段记录、负LCN增量、零/稀疏run、截断、重叠/越界、溢出、不完整映射、损坏USA及取消。新增明确跨首扇区尾字的属性编号反例，旧严格入口仍拒绝不匹配表示。
- 受控VHD比较同一批对象的IOCTL结果、原始严格结果与Native基准；留意锁前后时间点不同，不能把两者字节差异直接解释成某个缓存根因。成功仅证明本机受控静态夹具路径可用。
- 失败不自动回退为宽松解析、不修改系统日志、不安装服务。所有返回/取消/错误路径释放锁、缓冲和句柄，最后才由父脚本确认卸载并删除本轮镜像。
- 旧6条必要kernel样本保持本机，本轮首版不新增原始样本持久化，避免超出全局6条/512KiB。原始读取内容仅内存比对，公开摘要仅固定类别、计数与状态，不含路径、引用、卷标识、原始字节或哈希。
