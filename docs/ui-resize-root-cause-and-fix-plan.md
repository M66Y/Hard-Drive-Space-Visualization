# 连续缩放黑区：定位结果与针对性修复方案

进展：2026-11-15用户已确认按本方案实施。C47已提供默认关闭的原型与主窗受限候选，真实效果复审后再决定正常版接入；以下保留C46定位时的证据与验收条件。

2026-11-15，C46。基线 `9ac1f0b` 加继承的第一阶段工作区。本轮只添加测试诊断，不修改正常主窗绘制或正常开发输出。修复尚未实施，先由用户确认本方案。

## 已确认的原因

窗口扩大时，Windows 的原生客户区先变大，WinForms 的托管尺寸与子控件布局随后才更新。两者之间，新露出的右侧／底部区域暂时属于根窗口，尚未被图表、列表等子面板覆盖；背景擦除消息虽返回“已处理”，该区域仍可读到黑像素。后续布局与绘制完成后，同一坐标才被有效背景覆盖。

这不是仅凭消息顺序推测：纯画布 A 与当前 MainForm 的自有合成预览都采到了上述黑像素。A 不含客户区子 HWND，因此“原生列表必然是唯一原因”不成立；正常版仍有自己的重复透明背景绘制热点，不能把 A 的 `Opaque` 设置直接当成正常版的唯一成因。

### 正常主窗证据

- 相同的12步常用／最小尺寸交替，分别请求30 ms、100 ms间隔；两组均无日志截断或观察失败，均在5次扩大时采到20个有效黑点。
- 黑点全位于旧托管客户区之外、新原生客户区之内，属于尚未被子窗口覆盖的根客户区；同几何、同坐标的后续有效取点全部非黑，已由右侧主内容容器覆盖。
- 首次黑点时，嵌套 `WM_SIZE` 已返回，但外层 `WM_WINDOWPOSCHANGED` 尚未完成。托管尺寸在随后约11–19 ms更新，后续布局／同步绘制继续占用很久，不能说托管尺寸本身一直滞后两秒。
- 30 ms组中，图表／列表外层两个 `SplitterPanel` 的 `WM_ERASEBKGND` 分别83／94次，累计约9.036／5.991秒，占22.758秒采样跨度约66%。这些段没有其他已跟踪消息嵌套。两个面板设为透明；具体父背景调用链仍需在修复实现中核实，不能把未跟踪的方法调用写成已测事实。
- 根窗 `WM_PAINT` 本身累计只有约1.824 ms；正常版的长段主要处于尺寸消息及下游同步处理，不能照搬原型“整帧画了几百毫秒”的解释。

### 纯画布 A 证据

- 160步请求30 ms组，272个有效黑点全部位于旧已呈现画面之外、新客户区之内；272个同几何同坐标配对在 `FrameCopied` 后均非黑且匹配对应帧。
- 另一组无像素读取的同类诊断：整帧构建至复制 P95 约386 ms，实际尺寸请求间隔中位约312 ms。UI计时器被绘制占用，不能把“请求30 ms”称作实际达到30 Hz。
- 分段观测中，背景绘制不是主要成本；工具栏／卡片、列表文字与帧复制也占较大比例。不能先认定缩放壁纸是唯一热点。

## 证据边界

像素来自自有 HWND 的有效 GDI DC，并非直接测量 DWM 最终帧；用户已经明确确认屏幕上也存在黑区，不再反复询问是否肉眼可见。黑点至后续非黑点的时间只是采样夹逼区间，不是连续黑屏时长。`RootPaintReturned` 只表示根窗消息返回，不表示所有子控件在这一瞬间形成完整原子帧。

用户另一个助手报告 A 在慢速程序缩放干净、快速时有黑区，这作为用户提供的实测保留；本轮UI计时器没有达到同样的实际节奏，不能用本轮请求间隔替代其10 Hz／30 Hz比较。

当前尚未记录每次圆角 Region／裁切输入输出，因此半截标题的具体裁切分支未独立锁定。已确认存在原生尺寸、托管尺寸、子容器覆盖与最终画面之间的代际错位；该证据支持下面的修复方向，不代表所有裁切缺陷都已解释。最小化恢复黑块仍单列。

## 建议实施范围

1. **补上新暴露区域的真实背景。** 在原生客户区已扩大的阶段，按实际原生尺寸和本次几何快照绘制有效壁纸底图，检查背景擦除何时可以返回“已处理”。避免用旧 `ClientSize` 覆盖新区域，也不以暖白占位替代用户要求的背景效果。先在独立 A 原型验证，再给正常主窗做限范围对照。
2. **处理两个透明分隔面板的重复背景绘制。** 先用固定计数核实它们进入父背景／前景的调用链，再让一次尺寸变化内的背景、布局、圆角裁切共用同一几何代际；面板位置稳定后统一发布内容，减少重复擦除。不重新循环修改全窗合成、重绘锁或复制像素开关。
3. **按已测热点缩短空档。** 在 A 中分别优化卡片／工具栏、列表文字、静态图层复用及复制；在正常版中优先消除上述面板的重复工作。保留布局、背景裁切比例、双行列表和1.15倍沿边柔光。未测到前不承诺16 ms或固定帧率。

不新增扫描功能、不改系统设置、不录屏、不访问个人目录。不直接迁移正常版到单画布，不靠强制全窗 `Refresh` 或 `WS_EX_COMPOSITED` 掩盖问题。

## 验收与停止条件

- 沿用固定尺寸序列并记录实际请求间隔；分别检查尺寸刚变化、背景铺底、布局与裁切完成、内容发布各阶段，新增区域不能再读到有效黑点。维持对应有效像素覆盖，不能通过减少采样或把有效点改成未知来通过。
- 用同一几何代际核对背景坐标、标题裁切与图块／列表位置；完成帧必须保持壁纸和内容，不接受白闪、旧截图拉伸或松手后才重排。
- 两档DPI回归、自有目录主窗及原生控件兼容检查；GDI表面检查与真实屏幕体验分别记录。系统仍保留原设置，鼠标实时拖动未经验证就明确待验。
- 完成后先展示独立原型和正常主窗限范围对照的真实效果，由用户反馈决定是否接入正常版或第一阶段收尾。未通过则保留证据，不自动扩展为框架迁移。
