# 高速扫描：大型混合目录调度修正

日期：2026-11-07。基线：`7e519f1172ffed4f6f075fb67ca7b698498d6d5e`。用户已确认补测大型混合目录、优化高速调度、比较与自动的实际耗时；本轮为开发迭代，不打包、不创建标签或正式 Release。

## 范围与结论

原实现让多个目录各自发起文件并行，再竞争同一个八路文件读取许可。目录已经充分并行时，第二层调度没有增加可用 I/O 额度，却增加等待、任务与分配。新实现优先使用目录并行，只有目录不足时补充文件并行。自动、低占用、日志增量及元信息核验沿用原有策略。

混合目录额外托管分配明显减少；高速在平坦和多个大型目录样本中快于同轮自动，在大小目录混合样本中仍略慢。没有以人为拖慢自动制造差异，也没有把高速称为任何目录都最快。

## 关键实现与健壮性审查

| 文件 | 变化与约束 |
| --- | --- |
| `src/Scanning/FileReadBudget.cs` | 八路预算由目录任务与临时补充读取共享；目录按生命周期持有许可，补充读取只用非阻塞申请；取消等待者可退出 |
| `Core.cs` | 目录内超过 512 文件、没有排队目录且还有空余额度时才缓冲，最多 256 项一批；目录充分并行时直接读取，避免逐文件异步许可及额外任务 |
| `ScanPolicy.cs` / `RefreshStatus.cs` | 解释目录优先和适用范围，增加补充额度峰值；额度、原生文件调用峰值及目录任务数分开表述 |
| `tests/ParallelFileReadRegression.cs` | 预算归还、等待者取消、目录优先、异常/硬链接/未知占用、替换删除和写句柄等边界 |
| `tests/MixedScanBenchmark.cs` | 保留同一合成夹具用于前后比较，三种形态，每模式六次，校验逐项统计与状态 |
| `tests/FolderComparison.cs` | 用户明确指定目录才运行；真实主窗四次强制完整扫描，报告与隔离诊断放系统临时目录，拒绝报告目录位于扫描范围内 |

目录许可与补充许可总数不超过 8。补充任务不会持有一个许可再异步等待更多许可；批次读取全部结束即释放补充许可，再按枚举顺序发布。新目录在批次中出现时最多等待当前有限批次，不会无限扩展文件队列。最多八个目录各缓冲 256 项，新增文件记录硬上限仍为 2,048。

`Lease` 是内部单所有者的词法 `using` 资源，不复制或重复释放。取消、异常路径等所有已启动目录和批次任务退出之后才释放总预算。原生同步调用不能被立即中断，取消返回前仍等待其结束。文件身份、大小/分配量、硬链接汇总、失败/未知状态和迟到结果隔离均保留。

## 合成测量方法

在同一 SSD 上保留同一份合成数据：平坦目录 32,768 文件；32 个大型目录各 4,096 文件；混合目录为 16 个大型目录各 4,096 文件，加 2,048 组、每组四个叶目录、每叶八个文件，共 131,072 文件与 10,257 子目录。三组共 294,912 文件。每第 128 个文件为 8,192 字节，其余为 0–511 字节。

生产 `ScanCoordinator` 强制完整扫描，开启实时树发布但不绘制 UI。每模式先预热，再交替 AB/BA 六轮，每种形态十二次计时；前后各 36 次。显式 GC、夹具创建及逐项比较放在计时外。每次结果核对相对位置、类型、两种大小、修改时间、计数、共享/未知/不完整状态。原生身份与硬链接的等价另由专项回归检查。

以下为中位数，单位 ms。优化后列必须在同一轮内比较；环境不同导致前后绝对时间漂移，不能仅用跨轮时间断定变快或变慢。

| 形态 | 优化前自动 | 优化前高速 | 优化后自动 | 优化后高速 | 优化后高速相对自动 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 平坦 | 730.80 | 216.42 | 1,034.83 | 322.53 | 低 68.8% |
| 多个大型目录 | 9,703.99 | 9,254.42 | 12,900.47 | 11,526.17 | 低 10.7% |
| 大小目录混合 | 957.28 | 960.98 | 777.94 | 800.25 | 高 2.9% |

| 高速资源指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 大型目录总托管分配（字节） | 195,490,204 | 113,366,012 |
| 混合目录总托管分配（字节） | 171,230,744 | 130,282,176 |
| 混合目录进程 CPU（ms） | 7,984.38 | 5,734.38 |
| 混合目录批次文件数 | 57,344 | 0 |
| 混合目录文件缓冲峰值 | 2,048 | 0 |

优化后自动在大型/混合样本的总托管分配分别为 113,309,016 / 130,283,544 字节，高速额外分配已接近消除。分配总量不是保留内存或工作集峰值；进程 CPU 不是物理磁盘吞吐。自动模式的 `FileReaders=0` 表示未启用高速专用计数器，不表示自动只有一路读取。

所有原始样本见 `mixed-scan-before.json` 与 `mixed-scan-after.json`，包括优化后平坦自动首轮约 13.5 秒等明显波动，没有删除离群样本。未清空 OS 缓存、控制外部应用负载或测量物理 I/O，不能推广到冷启动、机械盘、网络盘、整盘或所有文件形态。统计口径、工具与预算约束均明确保留。

## 实际目录对比与隐私

只读比较使用用户明确指定的目录和生产主窗，顺序为自动、高速、高速、自动，各两次强制完整扫描，包含实际界面更新；不额外预热或清空系统缓存。每次完成后才计算逐项结果指纹，比较本身不计入扫描时间。目录变化时标记不一致，不把不同工作量当成相同快照。不能读取的条目保留不完整状态，不伪装成完整成功。

四次本机完整扫描均结束，统计数量一致，但完整指纹不一致。针对性复核进一步确认：成员集合、文件大小、实际占用、计数和状态一致，差异仅为目录修改时间；未发现本轮调度导致的漏算。该诊断额外保留逐项快照，其耗时与四次常规性能对比分开，不混合计算中位数。

真实目录的运行耗时有明显波动，针对性诊断也出现变慢，因此本轮**未证实高速在此目录稳定提速**。不能把一次较快结果推广为固定加速比例。跳过项继续保留不完整状态，未绕过核验或吞掉错误。公开归档不保存实际目录统计和耗时。

实际路径、文件名、统计数值、指纹、耗时报告和原始诊断不进入本归档或仓库。结果由本机验收与面向用户的交付说明报告，公开记录只保留执行及一致性状态；该比较不是大规模统计结论。
