# 高速完整扫描：有界文件读取并发

日期：2026-11-07。实现基线：`55b112d95bf9a058f08c664cfde3f78ff3995666`。用户在查看基线后选择“按建议实施（推荐）”，实施范围和验收约定见[方案](../../docs/scan-performance-plan.md)。本轮为开发迭代，不改 v1.4.2 版本字段，不打包、打标签或创建 Release。

## 实现与使用

选择“高速”后首次扫描或按 `Ctrl+F5` 强制完整扫描，大型平坦目录可以同时读取多个文件的元信息。前 512 个文件沿用简单路径，后续按最多 256 项的批次读取。每次完整扫描共享最多 8 路文件读取额度，8 个目录任务最多缓冲 2,048 项；不是 8 个目录各自再发出 8 路原生读取。小目录不建立批次缓冲。

自动、低占用及日志增量/元信息核验保留原策略。核验失败后实际回退为完整扫描且选择高速时，适用新路径。扫描详情新增实际文件读取调用峰值、并行批次文件数和文件缓冲峰值；不把它们当作物理 I/O 或 CPU 核数。

本轮已验证预览：`bin/ScanPerformance/DiskAtlas.exe`。普通输出中的启动程序被运行中窗口锁定，首次构建报 MSB3027/MSB3021；没有关闭用户窗口，改用普通构建的 `--output bin/ScanPerformance` 后，应用与测试均 0 警告、0 错误。此目录仅是开发预览，不是安装包。默认构建入口仍为 `bin/Release/net10.0-windows/`。

## 关键文件与健壮性审查

| 文件 | 本轮职责与检查 |
| --- | --- |
| `src/Scanning/FileReadBudget.cs` | 共享异步许可、活跃读取/缓冲计数，异常与取消归还许可；没有新增线程常驻服务 |
| `Core.cs` | 有限批次与异步目录衔接；批次所有读取结束后按枚举顺序发布，目录完成后才减少待办数 |
| `ScanPolicy.cs` / `RefreshStatus.cs` | 说明适用范围与文件读取峰值，保留原有目录/核验统计 |
| `tests/ParallelFileReadRegression.cs` | 真实文件、硬链接、受控竞态、取消和失败边界；测试钩子为 internal，正常生产使用原生读取 |
| `tests/UiRegression.cs` | 真实高速详情字段；主窗在批次中关闭时取消并等待读取回收，不回写结果 |
| `tests/ScanResponseBenchmark.cs` | 保持基线夹具/计时不变，只增加读取/缓冲统计字段，报告格式由 1 升至 2 |

枚举线程不创建每文件 Task，也不缓存整目录待读清单。文件任务只更新各自尚未发布的条目；最终计数与预览发布由目录任务负责，祖先统计继续逐节点加锁。许可只覆盖原生文件读取，不持有许可等待下游任务。批次异常或取消均等待已发出的任务收尾，清空引用并归还缓冲计数；随后主扫描等所有目录任务退出再释放预算。

原生文件身份、大小、实际占用、写句柄状态、链接数、重解析点排除及硬链接汇总仍用原逻辑。读取失败保留跳过/未知状态；未知占用不假装已知零。文件在枚举后被替换时采用实际读取的新身份与大小。实时文件系统扫描不是原子快照，取消不能强制中断正在执行的同步 Windows 原生调用；返回前会等待它结束。

## 验证结果

环境与基线同为 Windows x64、SDK 10.0.403、.NET 10.0.14 / WinForms 10.0.0.0，样本检测为 SSD。全部使用合成文件与隔离配置，不扫描真实整盘、不修改系统日志或权限。

| 检查 | 结果 |
| --- | --- |
| 应用与测试普通 Release 构建 | 最终均 0 警告、0 错误；应用使用上述独立输出 |
| 核心 / 高级 / 日志回归 | 38 / 25 / 16 项通过；真实 NTFS 刷新为 `ChangeJournal / Available` |
| `--parallel-file-tests` | 10 项通过：共享额度、取消等待者与许可复用、异常回收、硬链接一致、原策略隔离、12 个大型目录的全局额度/缓冲上限、批次取消、跳过/未知、文件替换、删除/写句柄及不完整回退 |
| 主窗 `--ui-regression`，144 / 96 DPI | 各 11 组通过，包含新增的批次中关闭主窗及迟到结果隔离 |
| `--response-benchmark` | 36 次完整扫描逐项一致、36 次取消恢复原结果；另 36 次元信息读取实验快照一致 |
| `--policy-benchmark` | 两次运行均逐项一致；第一次出现共享环境波动，按方案做一次针对性复核，未丢弃原报告 |

回归初次运行发现旧说明测试要求保留 SSD 的目录上限一致性，已补清楚“目录任务上限相同”。新增文件锁定测试起初错误地认为独占句柄必然阻止属性读取；实际 Windows 属性读取仍可成功并标记打开的写句柄，测试改为核对此正确行为，删除文件仍明确未知。以上仅最终有效结果计入表格。没有在检查通过后无条件重复全部背景/诊断专项。

使用 computer-use 实际操作隔离主窗：选择高速、`Ctrl+F5`、查看完成列表和扫描详情。8,001 文件显示读取峰值 8/8、批次文件 7,489、缓冲峰值 256/2,048；文字在详情窗口可读。验收窗口退出，用户原有窗口保持打开。没有归档桌面截图、用户配置或原始诊断日志。

## 同条件性能

真实主窗基准：每种形态均为 32,000 个 0–511 字节文件；先预热，三种模式按六种平衡顺序各运行 6 次。基线见[上一轮归档](../2026-11-07-08-scan-performance-baseline/README.md)。单位 ms，中位数：

| 高速指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 平坦：扫描返回 | 1,333.89 | 347.43 |
| 平坦：最终列表完成 | 1,448.22 | 418.75 |
| 多目录：扫描返回 | 295.57 | 285.13 |
| 多目录：最终列表完成 | 359.81 | 337.69 |
| 平坦：每次最大 UI 定时器间隔的中位数 | 162.26 | 78.22 |
| 平坦：搜索往返（含 220 ms 防抖） | 334.74 | 342.47 |
| 平坦：实际取消请求时间（目标为 75 ms） | 100.24 | 91.23 |
| 平坦：请求到扫描退出 | 63.64 | 78.23 |
| 平坦：整个取消测量往返 | 165.27 | 171.28 |

平坦完整扫描耗时减少约 74%，超过首轮 25% 目标；多目录没有回退。优化后平坦高速在全部 6 次运行中先于约 500 ms 的预览周期完成，因此没有观察到中间预览，最终列表比原首预览观察更早可用。自动平坦约 1,252.52 ms，低占用约 2,342.02 ms；两者没有启用文件批次。

平坦高速进程 CPU 中位数从 1,710.94 增至 1,843.75 ms（约 8%）；总托管分配从 28.82 降至 27.70 MiB；每次采样工作集最大值的中位数从 172.50 变为 174.17 MiB。这些不等于保留内存或精确峰值。取消请求至退出略增，整个往返增加约 6 ms；不宣称所有延迟都下降。读取峰值每次均为 8、缓冲峰值 256、并行批次文件数 31,488。

较小的无 UI 三策略基准另保存两份报告。第一轮多目录完整扫描自动/高速为 42.58 / 41.44 ms，相比原基线均较慢；暂停其他检查后复核为 35.36 / 34.81 ms，原基线为 35.00 / 34.75 ms。不能把第一次波动归因于单一原因，也不隐藏它。复核平坦高速完整扫描 56.76 ms，元信息核验刷新 164.41 ms；后者仍逐项核验，没有更改算法，不能将其数值变化称为本轮刷新提速。

保留报告：`scan-response-results.json`、`policy-benchmark-first.json`、`policy-benchmark-recheck.json`。计时原理、缓存状态及局限也写入原始报告；没有清空系统缓存、受控外部负载、整盘测试、机械盘/网络盘比较、实际鼠标到屏幕延迟或精确峰值内存测量。高速增加瞬时资源需求，不能推广成所有设备必然更快。首次扫描和强制完整扫描适用，未实施自动负载自适应或无日志核验提速。
