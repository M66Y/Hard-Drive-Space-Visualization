# DIB候选接入正常版：已确认，第一步两项修正已展示

2026-11-15拟定，用户随后明确同意实施，完成后先体验正常功能候选、再决定默认。2026-11-19先按30分钟范围完成[C49定位](../iterations/2026-11-19-49-mapping-audit/README.md)，随后用户明确要求修复这两项、先看DIB候选。现已完成[C50针对性修复](../iterations/2026-11-19-50-native-mapping-repair/README.md)并打开独立候选，用户已反馈“改善比较明显”；真实MainForm表面接入仍未实施。本方案不授权默认切换或更大的单画布迁移。

## 判断与交付目标

C48证明直接发布已绘好的DIB像素可以显著缩短候选的发布路径，但没有证明正常主窗的完整缩放已经顺滑。候选有合成场景渲染器，可以预绘下一尺寸的整页；正常MainForm由TableLayoutPanel、Label、Treemap、DataGridView、输入框等多个窗口表面共同绘制。不能直接复用合成场景代替真实界面，也不能只替换根背景便宣布等价接入。

建议交付一个**保留现有控件的正常功能开发候选**：迁入经过验证的DIB缓冲，接入真实背景／图表／列表发布，统一尺寸、背景与裁切的代际，再以真实扫描和交互验收。通过必要检查后先让用户体验；收到明确反馈后才决定将新路径设为普通启动默认。实现和验证合并推进，不为内部类或字段另拆确认；超出本方案的界面架构迁移再讨论。

## 明确保留

- 侧栏、工具栏、扫描设置、统计卡、路径／搜索、图表／列表、详情和进度的现有布局、尺寸规则与文字。
- 默认及自定义背景的裁切、焦点、透出强度、主题颜色和完整圆角；不通过遮住背景掩盖问题。
- 1.15倍沿边持续柔光、悬停／选中、进度图标泛光、减弱动效及隐藏停表行为。
- 七项核心功能，真实列表虚拟化／滚动／排序／分页／双行名称、键盘焦点、输入／中文输入法、复制和文件定位。
- 普通／NTFS扫描、取消恢复、缓存与两种大小统计逻辑。本轮不修改扫描器，也不因绘制验收触发个人卷raw或VSS。

不改系统拖动设置，不录屏，不迁移UI框架，不采用整窗Composited，不在缩放时隐藏内容或拉伸旧截图，不增加自动说明框／悬停文字。

## 具体实施顺序

### 1. 先补齐原生目标复制契约

把C48 `NativeResizeFrame`中与合成场景无关的资源／复制代码迁到`src/UI/Rendering/`，测试改为引用同一份生产实现，避免维护两套。

先重现All组合的26次`TargetOrigin`回退和6个几何后采样差异。记录拥有者表面、源／目标坐标、裁切和消息阶段，分清合法子控件覆盖、取点参照错误及实际内容错误。合法覆盖须有独立覆盖证据，不删除失败点或把未知当通过。

正常版需要从整窗背景源复制到局部控件。为此增加显式源矩形与目标位置映射，核对原生窗口原点、托管变换、可见裁切与DPI；每种新接受的映射先补逐像素反例。复杂／未知变换仍拒绝并回退，不简单撤掉`TargetOrigin`保护。6个差异未解释或仍有错误像素时，不启用默认路径。

### 2. 接入真实绘制表面，避免重复缓存

| 入口 | 接入方式与约束 |
| --- | --- |
| `WallpaperRaster`／`Wallpaper.Paint` | 将现有按窗口尺寸生成的背景缓存改为共享像素DIB源，保持CoverBounds裁切算法。模块按自身实际位置取相应背景，并按原样绘制浅色底与圆角，不从上次屏幕取像素 |
| `WallpaperTable`／分隔面板 | 使用同一背景代际；只在已验证的目标坐标上直接发布，减少透明面板重复请求父级绘制。标题仍用现有字体与控件，布局稳定后再核对Region |
| `TreemapControl` | 将既有静态层缓存接入DIB，不改面积布局、命中或标签算法；先恢复当前底层，再按原1.15倍节奏画沿边柔光，不为动画重绘整窗 |
| `WallpaperGrid`／滚动条 | 将既有固定底图缓存接入DIB；继续独立绘制可见行并保留原滚动事务。原生输入、选择、表头与滚动条不捕获进整窗截图 |
| 输入框、下拉框、弹窗 | 保留原生行为，验证覆盖／焦点／展开收起与背景取样协调；不强行截成静态图片 |

沿用每类缓存的像素上限，相关背景、图表、列表及过渡缓冲共同受128MiB像素存储预算约束；不是整个进程内存上限。新旧缓冲并存也计入预算，分配前检查，必要时先释放可重建缓存；不能临时突破预算。Bitmap视图与原生DC共享同一份存储，不额外保留一份相同旧缓存。

### 3. 将真实布局与发布放在同一代际

由`MainForm.WndProc`和现有`LayoutPresentation`共同协调：确认实际新客户区，准备匹配尺寸的背景，完成子控件布局与圆角裁切，再发布各表面的本代像素。不得在Paint里再次推动布局，不能每个子控件各自发起整窗同步重绘。

新暴露根客户区在可用的早期消息阶段发布同尺寸的真实背景；不把原型的“整页已就绪”假定搬到正常版。图表／列表的内容由其真实绘制路径完成，只有尺寸、DPI、背景、数据／选择版本都匹配且已完整初始化的缓冲才能复用。搜索、切工作区、背景变更、扫描预览等都会使相关缓存失效；新的空缓冲不能只画局部动效。

这能统一背景坐标和发布边界，但多个原生控件仍不是DWM原子提交的单帧。若剩余标题或子窗口闪黑无法在此结构内消除，保留具体失败证据，先向用户提出下一方案；不暗中改为整页自绘或大范围替换控件。

### 4. 回退与真实候选展示

保留旧绘制路径作为开发期对照，先用明确启动选项启用DIB，使用同一个正常MainForm与同一数据／配置条件比较。非支持映射、预算不足、句柄／DPI失效和复制失败时不能发布错误尺寸或未初始化像素；按原绘制器完成该次绘制并记录固定原因计数。持续失败时本窗口会话停用DIB，恢复旧路径，不能反复分配失败或静默宣称DIB生效。

这是故障恢复，不代表旧路径的闪黑已经解决。完成检查后打开具有完整扫描功能的DIB开发候选供用户体验；普通启动默认和正式包均在用户复审前保留原状态。最小化恢复先验证不退化，其原有黑块单独追踪，不因本轮局部改善关闭。

## 验收方法与停止条件

1. **像素与资源**：运行迁移后的DIB像素／复杂裁切／映射／资源循环，补齐子控件偏移反例、背景更换、超预算、句柄销毁／重建与DPI失效。支持路径零容差；无法支持时验证完整回退，不能发送空帧。重复缩放后句柄和缓冲恢复到明确的保有上限，窗口关闭释放。
2. **布局和表面**：两档DPI运行UI、表面、布局转换／呈现、背景、列表滚动／滚动条和Treemap状态检查。核对正常／最小窗口、所有三个工作区、长名称、输入焦点、下拉展开、侧栏磁盘卡片／弹层，以及默认／自定义背景。新旧路径相同状态逐表面比图，不因DIB改字号、透明度或布局。
3. **真实操作闭环**：用自建普通测试目录完成选择、边扫边显示、取消恢复、完成、刷新、搜索排序、双行列表滚动、切口径、目录进入／返回、复制／文件定位及弹窗。扫描与缩放并行时检查过期结果隔离和响应。仅使用合成数据及隔离设置；不默认复测个人NTFS卷。
4. **连续尺寸变化**：用真实MainForm测试入口在常用与最小窗口间跑同一固定序列，包含增宽／减宽、增高／减高和快速往返；慢／快两档请求，分别记录实际完成间隔。保持背景和布局，观察早期／完成阶段以及用户真实画面，不录屏、不依赖稳定截图宣布无瞬态。
5. **性能与体验**：同一目录、背景、窗口序列及负载分别比较旧／DIB路径；报告整次尺寸处理、分段成本与资源，不仅Paint耗时。不承诺30／60FPS；如果仍出现可见黑区、半截标题、背景接缝，或操作明显变慢，则本项未通过，先反馈失败位置与证据，不继续盲调或自动默认启用。

交付时先展示真实DIB正常功能候选、变化摘要和未验收项，等用户反馈后再决定默认切换。只有需要扩大架构、改变布局／背景／动效、调整系统设置或访问个人卷时才新增确认；已批准范围内的实现、必要验证和收尾合并完成。
