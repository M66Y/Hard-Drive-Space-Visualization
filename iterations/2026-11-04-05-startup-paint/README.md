# 启动首帧绘制修复

基线提交为 `68c41da9bdb3bedc2f36a49175ddbf71b2a0a387`。用户报告窗口启动时短暂出现大面积黑块和分批绘制的控件。

`MainForm.cs` 将 DPI 缩放、最终窗口尺寸及位置调整从 Shown 提前到 Load，并预绘一张覆盖整个客户区的背景。传入初始目录时仍从 Shown 启动扫描。`Wallpaper.cs` 按窗体客户区尺寸和原图共享预绘图，各控件按其窗口内偏移取图，仍各自绘制原有浅色覆盖。尺寸或原图变化时释放旧图，关闭窗口时释放资源。缓存上限 800 万像素，约 30.5 MiB，超出上限或分配失败时沿用直接绘制。

应用和测试构建均为零警告、零错误。新增回归断言 Load 到 Shown 尺寸及位置稳定、首帧复用预绘图，验证覆盖颜色、同尺寸复用、尺寸变化及超限回退。9 组界面回归在 144 DPI 和 96 DPI 虚拟化进程分别通过。实际启动预览后首张可捕获画面完整，未见黑块。没有逐帧录制从进程创建到首帧呈现的全过程，未量化冷启动耗时或验证其他显示器。

开发预览为 `bin/StartupPreview/DiskAtlas.exe`。合成夹具由测试清理，已清理构建中间物和 CLI 临时数据。未创建正式发布。`changes.patch` 为相对基线的可恢复补丁，`files.json` 保存 SHA-256。
