# 第 4 轮补验：多 DPI、长路径与高对比菜单

基线提交为 `bbb7ed3de16dfe7bb460487d647058db00291ac9`。

菜单打开时重新读取系统高对比状态。高对比使用 WinForms 系统渲染器及系统菜单背景和文字颜色，普通模式恢复明日香主题。文件列表和刷新菜单继续使用同一工厂。

应用和测试构建均零警告、零错误。8 组 WinForms 界面回归在 96 DPI 虚拟化进程和 144 DPI 桌面分别通过。检查路径框、搜索框、两个下拉框的内容边界，以及主窗两种尺寸。实际扫描含中英文且超过 270 字符的合成目录路径，核对文件列表、路径字段、完整选择和窗口绘制。系统配色通过程序内注入高对比状态，检查菜单打开、系统渲染器与颜色及恢复主题，并绘制菜单。未切换系统全局高对比主题，未验证其他 DPI 或跨显示器切换。

首次尝试以线程上下文创建 96 DPI 窗口，实际 DPI 未达到预期，测试明确失败。最终由独立进程使用 DpiUnaware，断言真实读到 96 DPI 后通过。测试命令为 `--ui-regression --dpi-96` 和 `--ui-regression`。

开发预览为 `bin/UiVerifiedPreview/DiskAtlas.exe`。合成夹具由测试清理，已清理构建中间物和 CLI 临时数据。未创建正式发布。`changes.patch` 为相对基线的可恢复补丁，`files.json` 保存 SHA-256。
