## 诊断结论

1. SSD 上自动与高速均为 8 路目录并发上限，策略配置本就相同。
2. 当前只并行处理多个目录，单个大目录内逐项读取文件元信息；配置 8 不代表实际使用 8 路。
3. 重新扫描可先核验并复用旧快照，不能与首次完整扫描的耗时直接比较。
4. 旧完整扫描在每个目录的最终统计发布时等待；旧核验只在同一目录累计满 256 项时等待。大量小目录下，两阶段的低占用节拍不同。
5. 旧扫描基准比较显式串行与默认 8 路，未通过三种真实策略入口；不能用它说明三模式体验。

本轮控制样本没有重现“低占用始终比高速快”，不据此否定用户在真实磁盘上的体验，也不将其他后台负载、缓存或目录结构造成的差异归因于单一因素。

## 实现与健壮性审查

低占用继续单路执行，完整扫描和核验各使用一个跨目录累计计数器：每 256 个目录任务或目录项按已有 3 ms 配置让步；实际等待受系统调度影响。不足一批不额外等待，缓存子树发布不附带固定等待。自动与高速不引入节拍等待，原来的并发上限和元信息读取逻辑不变。

并发计数器使用原子更新，并在 finally 中退出；报告的是执行中的目录任务峰值，含任务内等待，不代表 CPU 核数或瞬时磁盘 I/O。核验峰值与重建/扫描峰值分开保存。平坦目录在上限 8 下仍可能只显示峰值 1，这是当前实现的真实行为。

进度结构增加可选的阶段和并发上限字段，原有四参数调用仍可用。界面分别显示读取目录、核验元信息、复用缓存和统计整理；完成前不伪装完成，不新增虚假百分比。保持旧进度身份检查、取消恢复、缓存验证、硬链接去重、未知占用和只读分析行为。

计数器在所有枚举项处理前累计，包含新增、不匹配和重解析项，避免这些分支绕过节拍。等待前后检查取消，取消不转成普通读取失败。目录错误跳过与错误统计仍走原路径。

## 前后基准

无日志刷新通过注入不可用日志接口固定核验路径，不把模拟的日志情况说成实机日志可用。包含实际扫描协调器、同步限频进度和预览会话记录，不包含样本创建、验证指纹、计时前 GC 或界面绘制。未清空操作系统缓存，也未扫描个人目录或整块磁盘。
