日期：2026-11-07。基线：`b0df83df45485f88b8820a6dc6c025ab52b6ce02`。用户已选择“按完整建议实施（推荐）”，实施契约见 [本地诊断方案](../../docs/local-diagnostics-plan.md)。这是普通开发迭代，不更改 v1.4.2 产品版本字段，不打包、打标签或创建 Release。

## 范围与结果

主窗“背景设置”旁新增“诊断”，可在扫描中打开且不阻止主窗操作。运行诊断提供本地开关、级别/时间筛选、中文摘要、清空及勾选后预览导出。问题记录支持主动新增、编辑、删除，开发记录说明继续指向 Git 与迭代归档。用户步骤见 [诊断说明](../../docs/diagnostics.md)。

运行诊断首次默认开启；设置损坏时暂停，开关失败不谎报生效。关闭控制结构化日志及最近异常文件，等待当前写入并丢弃待写事件。8 个分段各不超过 1 MiB，总计 8 MiB，保留 14 天；最近异常另保留单份小于 512 字节的白名单报告，同样按 14 天清理。队列最多 128 条，每条不超过 1 KiB，过载报告遗漏。笔记最多 100 条 / 1 MiB，标题 100、正文 2,000 字符，容量先达到者生效。

白名单只接受固定事件/状态和必要计数；未序列化扫描对象、路径、名称、字节总量、原始异常、图片或任意字符串字典。临时会话标识每进程生成。旧异常格式没有构建版本，读取时不伪造为当前版本。损坏记录与多余字段拒绝进入导出，预览是固定快照，原子保存逐字节一致。自由文本问题记录不加入导出，也不自动附加任何资料。没有联网、遥测或上传功能。

扫描选择、回退和取消算法未改变；新增固定 `RefreshReason` 原因码，并在生产主窗记录开始、阶段变化、完整/部分完成、取消、失败与背景操作错误。日志不可用时的元信息核验仍然保留，不能把诊断功能称为刷新提速。

## 关键文件与健壮性审查

| 文件 | 职责与检查点 |
| --- | --- |
| `src/Diagnostics/DiagnosticRecord.cs` | 固定字段、枚举校验、大小限制、旧报告严格解析、中文摘要和重新生成的导出 |
| `src/Diagnostics/DiagnosticStore.cs` | 有界读取、轮转/保留、原子保存、250 ms 跨进程互斥、设置代次、笔记修订冲突 |
| `src/Diagnostics/DiagnosticService.cs` | 后台顺序写入、128 条队列、过载计数、开关/清空屏障、有界退出 |
| `src/Diagnostics/DiagnosticsDialog.cs` / `DiagnosticEditors.cs` | 非模态入口、筛选、选择、预览、笔记编辑、主题、关闭后的结果隔离 |
| `Program.cs` / `MainForm.cs` / `BackgroundDialog.cs` | 生产生命周期和必要事件接入；异常存储不占用 UI 线程 |
| `ScanPolicy.cs` / `ScanCoordinator.cs` | 只添加固定刷新原因表达，保持现有扫描决策 |
| `tests/DiagnosticsRegression.cs` / `DiagnosticsUiRegression.cs` | 存储、隐私、竞态、跨进程、生产 UI 及隔离人工验收入口 |

清空先提交设置代次再删除已知文件，跨实例的旧批次无法回流。设置/笔记采用原子替换，失败保留旧文件；笔记版本冲突拒绝覆盖。临时副本属于明确的本模块文件名，遗留异常临时副本只处理合法 GUID 命名。清空保留笔记、背景、原文件与导出；删除/写入前拒绝重解析点。故障不递归写成新故障日志。

某个文件锁定时仍可读取其余诊断，明确显示清理/存储不完整；不把未完成清理说成成功。数据损坏不会被当作空笔记覆盖。只在勾选后生成导出；窗口关闭后的异步结果不再写控件。问题记录未选中时编辑和删除禁用。
