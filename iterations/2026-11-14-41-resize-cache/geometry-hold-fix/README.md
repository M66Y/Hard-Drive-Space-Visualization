## 四份源码的改动

- `MainForm`只在有效客户区或窗口尺寸发生改变时申请几何原生重绘持有，跳过纯移动、最小化和恢复路径，继续覆盖外层WM_WINDOWPOSCHANGED及直接WM_SIZE。没有将整窗WS_EX_COMPOSITED或纯色过渡加入产品。
- `LayoutPresentation`让取得的内容根重绘持有延续到最终布局与圆角裁切稳定后，再释放并呈现。按祖先深度获取，避免重复持有后代；已有外部持有不被擅自接管，空事务不增加无效重绘。
- 最终清理逆序尝试释放全部本次token；取得过程中发生异常时保留原异常并清理已取得部分。代际、句柄销毁/重建和最终呈现重入分别隔离，旧token不能释放新一代持有。事务内隐藏的控件不因WM_SETREDRAW(TRUE)而被强行显示，显式Show后再恢复。
- 两个测试文件补充真实MainForm.Resize接线、独立根/祖先根/外部持有、嵌套与空事务、最终裁切异常、隐藏/显示及WM_SETREDRAW期间销毁重建等受控检查。

曾尝试覆盖GetVisibleCore异常的测试，但该override不成立，编译失败后已移除，不计入验证；保留实际WM_SETREDRAW消息中的句柄重建反例。曾尝试用owner.Paint计数、owner.Update/Invalidate断言确定根因，但Dock子控件可完全覆盖owner待绘区，断言不可靠，已精确撤回，不把它当根因结论或继续叠加补画。
