# C41后续：减少分隔容器重复背景擦除（已有改善，仍待实际复审）

2026-11-14。沿用用户批准的缩放修复范围，保留现有布局、背景透出、圆角、无说明框/无悬停文字及1.15倍沿边柔光。本候选减少了一处已复现的重复绘制；同一程序控制序列耗时下降，但仍存在明显阻塞，不能宣布半截标题、背景割裂、黑边或整体卡顿已经解决。

## 证据与改动

此前线程采样指向背景擦除，测试专用的有界消息观察进一步按控件类型统计自有窗口的WM_ERASEBKGND/WM_PAINT次数和同步耗时，不采集屏幕、不发送输入、不改变系统设置。最多观察256个自有句柄，结束解除；嵌套消息耗时可能重叠，不相加冒充总耗时。

`WallpaperSplitContainer`原先启用了OptimizedDoubleBuffer和ResizeRedraw，却没有AllPaintingInWmPaint，独立背景擦除仍会先重画壁纸。旧样式反例以`StandaloneEraseDoesNotRedrawWallpaper`失败。单独改成`DoubleBuffered=true`也失败：OptimizedDoubleBuffer原已为true，该setter没有补齐缺失样式。

当前显式设置`AllPaintingInWmPaint | OptimizedDoubleBuffer | ResizeRedraw`，将该控件的独立擦除留给正常缓冲绘制路径；不改背景内容、透明度、模块位置或原生锁默认值。新增测试核对擦除被处理但不绘制壁纸，正常客户端与后续Paint仍能恢复背景，不能只靠静态样式标记宣称有效。两档DPI各6项通过。

`LayoutTransitionPreview`新增的有界观察与分段计时仅为测试工具；`Program`只接入新专项入口`--wallpaper-background-erase-tests`。本子归档冻结四份源码，不修改父目录原五文件截点。

## 同条件受控观察

两次均关闭OBS，使用同一1106文件自建目录预览，程序控制24步缩小再放大并恢复原尺寸；这不是鼠标原生拖动、真实帧率或普遍性能基准。

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 完成步数 | 24 / 24 | 24 / 24 |
| 序列总耗时 | 36,260ms | 24,655ms |
| 最慢同步Size设置 | 1,003ms | 760ms |
| Size设置累计耗时 | 19,165ms | 12,475ms |
| 步骤等待累计耗时 | 17,092ms | 12,175ms |
| Split容器96次背景擦除累计 | 7,394.271ms | 0.034ms |
| Split容器24次Paint累计 | 2,009.241ms | 34.595ms |

该单组、固定顺序观察显示改动方向有效，仍受缓存和外部负载影响。等待耗时含消息泵调度延迟，不等于主动添加的60ms全部等待。消息耗时存在包含关系，不与序列总耗时累加。改后SplitterPanel的192次背景擦除仍累计8,053.801ms，主要卡顿尚未消除；不能以局部接近零的擦除时间代表整个窗口流畅。
