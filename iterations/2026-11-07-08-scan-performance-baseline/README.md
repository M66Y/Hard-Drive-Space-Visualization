## 范围与证据

- `tests/ScanResponseBenchmark.cs`：既有生产主窗与原生读取基准；`tests/Program.cs` 只增加可选入口。
- `policy-benchmark-results.json`：既有三策略基准，15,200 个合成文件，完整与无日志刷新各六轮。
- `scan-response-results.json`：32,000 文件平坦/多目录各六轮三策略、真实主窗 144 DPI、独立开启的诊断配置；另测 1/4/8 路现有原生读取。只保留固定场景标识、计数和数值，不保存真实路径、身份、名称或诊断日志。
- 测试构建 0 警告、0 错误；核心 38 项、高级 25 项通过，真实刷新报告 `ChangeJournal / Available`。两组基准全部通过，36 次计时 UI 扫描逐项相同，36 次取消保留此前完整结果。生产代码未变，未无条件重跑全部 UI、背景和诊断专项。

环境：Windows x64、SDK 10.0.403、.NET 10.0.14 / WinForms 10.0.0.0，合成目录检测为 SSD。UI 基准在真实桌面执行；预热后采用六种平衡模式顺序，GC、夹具创建、结果比对在扫描计时外。两份报告记录全部有效计时样本，结论采用中位数。

32,000 文件平坦高速扫描返回 / 列表完成为 1,333.89 / 1,448.22 ms，多目录为 295.57 / 359.81 ms。平坦首预览观察 660.66 ms；目标 75 ms 的取消实际请求 100.24 ms，请求至退出 63.64 ms。平坦原生读取 1 / 8 路为 981.17 / 188.40 ms，但 CPU 从 953.12 增至 1,468.75 ms。原生实验不含枚举、建树、汇总和 UI，不作为软件加速倍数。

## 健壮性与局限

基准检查每个完成条目的相对位置、类型、大小、分配量、时间、计数、共享占用、未知量及不完整状态；原生快照另核对身份、链接与写句柄状态。取消使用生产控件并核对旧结果对象保留。独立诊断目录不触碰用户配置；已有输出拒绝覆盖。每次 UI 等待有超时，线程未退出时保留夹具，进程退出后再清理，避免与正在执行的扫描争抢删除。

尚未测整盘冷扫描、物理 I/O、受控外部负载、跨屏、真实输入到屏幕延迟或精确峰值内存。UI 调度间隔不是帧率，工作集仅定时采样；低占用整次 CPU 在部分样本中更高，不能据此宣称低占用已经全面降低资源。多目录快速扫描在部分预览周期前结束，未观察到部分预览记为 null。此次没有产品界面改动，不新增视觉验收结论。
