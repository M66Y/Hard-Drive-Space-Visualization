## 先失败，再修正

新增`tests/ScrollFrameConsistencyTests.cs`使用真实MainForm、生产名称绘制回调、自有纹理图片及160条合成数据，跨可视区各列取固定背景点。在Scroll入口、事后Invalidate/Update之前观察未经保护的客户区像素，不用DrawToBitmap或等待补画。最初只做整屏往返时没抓到背景搬移，却先暴露延迟模式松手不移动实际行；补入小幅连续拖动后，旧代码两档分别出现11/14次背景搬移，96DPI输入返回时还观察到16次背景不符。松手不移动实际列表各3次。原失败日志只留本机，精选固定字段见verification-summary.json。

这证实新指针直接Scroll事件入口未被既有缓冲保护覆盖，之前的事后整块补画无法阻止搬移到补画之间的旧背景曝光。保留C63修复及用户当时接受事实、C64扩展视频的残留，不将之前通过改写为从未失败。

## 修复

`ScrollbarPointerTracking.Emit`将原Scroll事件和调整后的NewValue一起放进`WallpaperGrid.PerformBufferedScroll`，共用滚轮/键盘已有的局部保护。`RestoreRedraw`只恢复、标记待发布；`PresentScroll`先完成固定背景和可见列表绘制，再通知原生轨道发布。仍保留原控件、范围/事件/UIA、所有权与取消/异常恢复，不新增HWND、每帧整树I/O或全窗刷新。

DataGridView消费ThumbTrack来移动行，延迟模式只有ThumbPosition会漏掉实际移动。现在延迟拖动期间不提交，松手时补交一次ThumbTrack，再完成ThumbPosition、捕获释放和EndScroll；即时模式不重复补交，尊重处理器调整后的值。系统偏好只读，测试以对象注入覆盖两种模式，不修改Windows设置。
