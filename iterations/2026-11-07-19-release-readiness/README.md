## 结论与实现

本机核心使用流程、安装/源码交付和离线工具已经分别有证据，但没有正式候选资产对应的全通过记录，也没有干净系统或真实远程草稿验收。详见[集中清单](../../docs/release-readiness.md)。本轮通过连接器只读查询 Release 返回空列表，`git ls-remote --tags origin` 返回空列表；未创建、移动或删除标签。PATH 中未找到 GitHub CLI，未读取令牌或宣称 CLI 已登录；正式上传前仍需准备执行环境和核验权限。

实际发现：`Upload-Draft.ps1` 之前只检查标题/版本/两种语言，即使缺少安装方法、已知限制和下载链接也能通过。新增 `docs/release-notes.template.md`，提供两种语言各七个栏目、四类资产/校验清单链接、当前许可、未签名状态和使用边界。模板保留版本/提交/运行时/具体变化占位符，不能当作已定稿说明或公开下载。

`scripts/release/Release.Common.ps1` 新增 `Assert-ReleaseNotes` 并由真实上传入口调用，在调用 GitHub 前核对精确标题、栏目与内容、未替换占位符、实际清单的运行时、签名说明、六个下载校验 URL 与源码提交。注释和围栏代码不能填充正文；重复语言/栏目、错误版本及仅前缀相同的运行时、错误仓库/链接会被拒绝。检查不替代人工判断文案真实或中英文等义。

关键工作文件：上述两个生产脚本、发布说明模板、`tests/ReleaseNotes.Tests.ps1`、`tests/DraftUpload.Tests.ps1`、集中缺口清单，以及规则、状态、计划、发布/测试手册和中英文入口。程序源码、扫描算法、安装器和正式版本字段未修改。
