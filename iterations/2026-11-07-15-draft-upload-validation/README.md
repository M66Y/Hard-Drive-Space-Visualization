## 发现与实施

此前脚本已验证部分草稿保护函数，但没有执行完整上传控制流程。新增 `tests/DraftUpload.Tests.ps1`，复制未经修改的生产 `Upload-Draft.ps1` 与公共函数，通过原生 `gh.cmd` 替身运行 `tests/fixtures/release/FakeGitHub.ps1`。替身只实现本地状态与文件复制，未知命令立即失败，没有网络、凭据、发布或删除能力；测试结束恢复 PATH 并清理自有夹具。

测试真实复现：要求 `v1.4.2` 时，只含 `v1.4.20` 的发布说明仍能走完上传。这是原先 `Contains` 子串匹配造成的。生产脚本改为完整版本标识匹配，拒绝后缀版本、四段版本和大小写不一致。

审查还发现续传只校验草稿状态和资产，未核对标题与说明。增加统一核验：草稿标签、标题及已审查的双语说明必须一致，仅允许 CRLF/LF 和末尾换行差异。首次发现、每次上传前及最终下载后都核验；不自动改写既有草稿。无关应用功能、扫描策略和正式版本号保持原样。
