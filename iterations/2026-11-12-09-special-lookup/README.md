## 实现与大小契约

`NtfsSpecialLease` 仅支持单一 Compressed 或 Sparse 理由的基记录默认流，保留未知分配，直到同一只读句柄的两组元信息均通过。每组 Basic/Identity/Standard/Compression/Basic；前后属性、修改/变化时间一致，完整身份、EOF、可见链接数、非目录/待删除、格式及分配量也需匹配。压缩限定 LZNT1，稀疏限定未压缩格式，不套用分配小于逻辑长度的假设；合法零可发布，未知仍是未知。

`ResolveSpecialWithLease` 复用有界批次守卫和来源模型，原驻留入口不变。最多 4096 个对象，重复身份、槽复用和路径冲突等在读取前拒绝；失败不缓存，取消丢弃本批部分结果。组合理由不执行补查，分配保持未知。引用名、原始记录、父目录关系和整卷一致性并未由文件句柄证明。

只分享读取，不因分享冲突改用宽松打开；句柄在提前返回、异常、取消中释放。可以拒绝已有数据写入/删除句柄，但不能证明读记录到打开句柄之间未发生同 EOF 写入，也不能排除仅改属性和观察之外的变化。未在真实原生调用内部注入竞争，取消不能打断同步系统调用。这仍是原型，不是活跃卷快照。

## 保留的失败与未完成项

本轮前三次均因严格 `DecodeKernelReturned` 的 USA 表示检查失败而停止，不与成功样本合并：

| 证据 | 检查数 | 当时夹具变化 / 失败码 |
| --- | ---: | --- |
| attempt-01.json | 111 | 新增特殊硬链接和较长命名流名称；FixupMismatch |
| attempt-02.json | 147 | 增加默认流持久刷新；FixupMismatch-Case6-P0-R1-S2 |
| attempt-03.json | 215 | 移除新增特殊别名、增加命名流刷新；FixupMismatch-Case11-P0-R1-S2 |

P/R/S 为当次记录中匹配保护标记、保存值的扇区尾字数及扇区总数；Case 是当次调用顺序，不能按最终夹具顺序反推全部早期变体。后续 `U` 只记录受控的使用长度。第一次失败时尚无这些诊断计数。没有保留原始记录或完整失败源码快照，表中只保留会话确认的生成条件，不能声称可字节级重放；实际失败码和卸载/清理状态保留在独立摘要。

最后限定形态移除新增特殊别名、将两个组合夹具名称缩短为 c.a / s.a 后通过。此举只隔离特殊补查与组合拒绝的目标，未修复较复杂记录的读取表示。解码器本轮未改动、未跳过校验。刷新没有消除失败，根因尚未证明；不将它解释为磁盘损坏。微软的 [IOCTL](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_ntfs_file_record) 与[输出结构](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-ntfs_file_record_output_buffer)没有承诺 USA 表示或原子快照；[MULTI_SECTOR_HEADER](https://learn.microsoft.com/en-us/windows/win32/devnotes/multi-sector-header)说明保存数组与磁盘写入相关，但目前不足以确定本机失败原因。

后续先研究 NTFS-01-KERNEL-USA 的可靠表示/恢复策略，再扩大真实复杂记录支持。命名流、属性列表/扩展拼接、更多格式/几何、Windows 10、真实组内竞争、活跃卷协调、整卷 MFT 批量读取及生产后端仍未完成。没有接近 WizTree 速度的证据。
