# Windows PowerShell 5.1 离线验收工具

日期：2026-11-07。实施基线：`a1050a97e4755cc39750a44a9e312dcf93004b23`。用户已选择“按方案开发离线验收工具”，范围见[已确认方案](../../docs/offline-acceptance-plan.md)。本轮完成工具开发和本机验证，不将缺少独立干净环境改写为通过，不启动已延期的性能优化。

## 实现与关键文件

- `scripts/acceptance/Acceptance.Common.ps1`：环境证据、清单与资产哈希、便携 ZIP 路径/内容/运行时/许可核对；合成样本与私有会话；进程隔离启动、人工结果、白名单报告、归属清理。
- `scripts/acceptance/Invoke-Acceptance.ps1`：Prepare / Inspect / Start / Record / Export / Cleanup 入口；静态错误码，不打印异常全文。
- `tests/OfflineAcceptance.Tests.ps1`：实际 Windows PowerShell 5.1 下的合成资产、独立进程与 CLI 边界检查。
- `docs/offline-acceptance.md`：开发机与目标机职责、操作清单、记录与失败恢复。同步项目规则、状态、开发计划、发布/测试手册及双语 README 的目录说明。

工具不依赖 PowerShell 7、Git 或现代 .NET；使用 Windows 自带 .NET Framework 能力。输出默认 pending，将人工声明与自动事实分开，报告始终 `release_gate=not-evaluated`。源码两种包和安装器只核对整体哈希，不重复实现开发机的源码内容/编译与安装验收；四类资产仍须先通过既有生产校验。

## 验收与健壮性审查

`checks.json` 记录最终 **98 项断言通过**，运行宿主为真实 64 位 Windows PowerShell 5.1。本机识别已有现代 .NET；未改变 PATH 或卸载运行时制造“干净”。检查覆盖错误清单/版本/资产、ZIP 越界、重复和目录冲突、链接、缺失/内容哈希、运行时与许可、提取后载荷变化、默认待验收及报告绑定。报告白名单排除合成私人路径与未许可字段，CLI 绑定失败只输出固定错误码。

使用内置 .NET Framework 编译能力生成一次短时合成子进程，仅用于测试进程环境和活动状态；目标入口自身不调用编译器。验证只为子进程传递数据目录，父进程环境保持原值；重复启动、运行中清理和提前记录正常退出均被拒绝。原子写失败保留旧状态并清除临时文件；中断准备拒绝启动；清理遇到占用先保留归属与 cleaning 状态，释放后重试成功。目录链接在递归删除前拒绝，未知目录和源资产保留。进程记录只保留最近一次，避免不断增长。

兼容检查中修正了显式加载压缩程序集及空备份路径的 Framework 调用方式。测试 ZIP 使用生产同款正斜杠路径，避免旧 Framework 的生成差异掩盖测试条件。最终脚本均保留 UTF-8 BOM。源代码中的合成私人路径只是泄露检查夹具，不是本机用户信息。

## 范围边界、清理和恢复

本轮没有修改应用源码、运行扫描性能基准、构建软件或打包；没有安装工具、启用 Windows 功能、创建 VM、运行发行 EXE、标签或 Release，也未访问真实草稿上传接口。合成测试不能代替真正发行载荷、干净 Windows 和正式候选资产验收；这些门槛继续保留，既有真实 EXE 的本机证据仍来自[第 16 轮](../2026-11-07-16-executable-workflow/README.md)。

本轮测试夹具、合成 EXE、报告副本、隔离目录与链接已删除；保留正常开发构建、用户数据、依赖和历史证据。`changes.patch` 只包含本轮工作文件，以实施基线恢复；`files.json` 保存清单、SHA-256 和补丁恢复核对。文档链接、隐私和空白检查记录于 `validation.json`，清理结果记录于 `cleanup.json`。不归档原始终端输出、私人路径或大型二进制。
