# C79 快扫内部计时与补查归因

2026-11-28，基线 `f07105e68e66d32177cd304865c1001cf6fb4634`。接续 C77/C78 的审查结论，按用户“继续后续任务、减少停顿”合并实现测试工具的三个缺口：来源准备分段、补查原因、索引收尾。没有执行新的真实卷、快照或原始页读取。

## 实际改动

- `NtfsScanDiagnostics` 只保留五段耗时、唯一对象数及 128 个原因组合桶。空缺不伪装为零，时钟、容量和总数一致性受校验。多原因对象只进一个组合桶，硬链接别名不重复计数。
- source/VSS 在现有动作外加可选计量，原路径 pins 仍由原 `finally` 释放。索引计时从并行补查全部结束后开始，大小规则、权限、句柄核验、容量及取消清理保持原状。移除未使用的逐对象布尔字段，新增原因标记仅用一个字节。
- 测试 apphost 使用新的 detailed 入口；默认软件和旧计时不采集。诊断帧经原绑定管道，仅在已确认清理及完整结果解码后对调用者可见。补齐“诊断后结果失败”与“已清理后回调失败”的终态处理，防止误报清理未知。
- 隔离盘脚本显式 `-Detailed`，前后端双向绑定模式，严格接收固定字段并交叉核对对象数与补查阶段。信封大小与单行 JSON 上限分开；普通端重算白名单摘要后才输出，拒绝未知字段和被篡改的清理状态。

测量定义、使用入口及限制见[计时工具](../../docs/ntfs-product-timing.md#c79-可选的助手内部诊断)。新采集有少量开销，不能把 detailed 与旧模式无条件混作同一性能样本；每种原因的 I/O 耗时、独立人工等待、DWM 呈现均未测量。
