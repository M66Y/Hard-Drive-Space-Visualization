# 第 2 轮修正：头像进度、回弹与悬停绘制

日期：2026-11-02。基线提交：`ee7f8edb266690e624c2b40c967cdb59593ebc39`。

## 需求与范围

用户反馈三点：移动透镜改为软件头像、进度颜色适配；果冻感不明显；扫描完成后跨图块悬停的深色边框卡顿。用户明确要求现在实施此前建议的修正。本轮只做这三项，不改变扫描、统计、增量可靠性或文件操作。

## 关键决策与文件

- `ScanProgressControl.cs`：改用现有 `assets/app.ico` 的明日香头像，红到暖橙渐变与头像配色呼应。头像以约 26 个设计像素显示，保留透明边缘；按 DPI 缩放并缓存，仅尺寸变化时重新解码。标记左右留白避免首尾裁切，文字与标记分行留出空间。进度估算、未知总量、取消/失败/不完整结果规则不变。
- 应用和测试项目显式内嵌同一 ICO，复用既有资源，不引入图片副本和外部依赖。
- `TreemapControl.cs`：普通悬停、移出和选中只失效旧/新图块，消除原来无参数 `Invalidate()` 造成的全图刷新。静态背景、基础图块、嵌套布局与文字绘制到单张视口缓存；每帧只恢复裁剪区域并绘制悬停/选中/高光，悬停不重建静态图层。
- 缓存最多 800 万个 32 位像素，图像数据约 30.5 MiB；这是新增图层的上限，不是总进程内存上限。布局和大小改变时释放，DPI、背景图引用、窗口尺寸或相对位置改变时重建；口径和嵌套显示切换主动失效。隐藏和销毁释放图层；超限或分配失败降级为局部直接绘制，并记住当前失败状态，避免每帧反复尝试分配。
- 回弹增强为约 620 ms，16 ms 目标定时器间隔，最多一个图块。内部渐变高光和轮廓做更明显的横纵挤压、衰减回弹；外部面积、文字坐标、嵌套布局和命中区域固定。16 ms 不代表所有环境都能达到 60 FPS。
- `MainForm.cs`：默认开启动效，继续提供“减弱动效”，仅本次运行有效。此前借用系统“窗口最小化/还原动画”开关会让内容动效默认关闭，导致用户看不到回弹；现在不再将二者绑定，不修改 Windows 设置。
- `tests/TreemapBenchmark.cs` 与入口：新增合成悬停绘制基准；`tests/UiRegression.cs` 增加缓存、资源与局部绘制验证。README 和使用说明同步行为及本轮独立预览入口。

- 原有图块面积与命中、动效关闭和隐藏停止、真实进度终态、迟到回调检查继续通过。回弹持续时间检查同步为 620 ms 加调度余量。

## 同条件绘制基准

相同合成数据、1280×760 视口、144 DPI、有背景图、关闭动效；一轮预热后五轮往返目标顺序。计时包含悬停处理及相应裁剪区的离屏 GDI 绘制，不包含扫描、样本创建、窗口创建或操作系统呈现延迟。修正前后分批执行，可能受系统调度和后台负载影响，不能当作实测鼠标到屏幕延迟或固定 FPS。

| 合成场景 | 中位耗时：修正前 → 后 | P95：前 → 后 | 每事件托管分配：前 → 后 | 刷新矩形面积中位数占比：前 → 后 |
| --- | --- | --- | --- | --- |
| 12 文件夹，各 36 个嵌套图块 | 31.2106 → 0.6836 ms | 32.4656 → 1.3216 ms | 26,963 → 864 B | 100% → 16.20% |
| 241 个平坦文件 | 20.3115 → 0.1308 ms | 21.4503 → 0.4249 ms | 41,555 → 925 B | 100% → 0.91% |

这里只证明合成场景中重复绘制成本大幅下降。未测真实整盘结果、物理鼠标呈现延迟、操作系统调度下的稳定帧率或其他 DPI/跨屏；不宣称扫描速度提高。图层重建需要一次完整静态绘制，以上为缓存预热后的数字，新增图层有明确内存代价。

## 复现、归档与清理

构建测试项目后在正常桌面执行 `dotnet tests/bin/Release/net9.0-windows/DiskAtlas.Tests.dll --treemap-benchmark after`。结果写入 `artifacts/treemap-after.json`，已有文件必须先归档再运行，避免覆盖。

复现修正前基线：在独立检出切到上述基线提交，将本轮 `tests/TreemapBenchmark.cs` 放入测试项目，并在测试入口加入同样的 `--treemap-benchmark` 分支，再以 `before` 标签运行。基准不读取个人文件，目录项为内存中的合成数据。完整摘要保存在 `benchmark-before.json`、`benchmark-after.json`。

`changes.patch` 保存关键文件相对基线的变更，不递归包含归档自身；在干净基线上用 `git apply --binary` 恢复，按 `files.json` 核对 SHA-256。Git 历史保存包含本目录的完整提交。
