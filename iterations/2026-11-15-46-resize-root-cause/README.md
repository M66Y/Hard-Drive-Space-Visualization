# C46：连续缩放根因定位

2026-11-15，Git基线 `9ac1f0b`，承接C30暂存及C31–C45未提交工作区。用户要求先查清黑区表面／绘制阶段，给针对性方案后再实施。本轮只有测试诊断、证据整理与方案；正常绘制代码、普通开发输出及正式v1.5.0不变，未修复或宣告视觉通过。

## 结论

**新原生客户区先暴露，根表面尚未被有效背景覆盖；正常版后续透明面板的重复背景处理又延长了这段呈现空档。**

纯画布A的272个有效黑点、正常MainForm两组各20个黑点均在新区域，后续同几何同坐标有效取点全部非黑。正常版黑点在嵌套WM_SIZE返回、外层WM_WINDOWPOSCHANGED尚未结束时，属于没有子窗口覆盖的根客户区；之后归属扩大后的右侧主内容容器。不能把WM_SIZE返回误称为“子控件布局已完成”。

正常30ms组中，两个透明SplitterPanel的WM_ERASEBKGND分别83/94次、9.036/5.991秒；100ms组为83/94次、9.271/6.195秒，均占记录跨度约66%。这些是无其他已跟踪原生消息嵌套的热点；父级包含时间不能重复相加。根WM_PAINT本身很轻，不能说它画了两秒。父背景调用链有源码支持，但未采托管调用栈／运行时Panel样式，不能把177次擦除或全部耗时直接等同于壁纸绘制。

用户提供的外部录屏结论“A慢速干净、快速有黑区”作为其实际观察保留，用户亦明确黑区一直真实可见；不再重复询问。此任务没有录屏或操作OBS。

## 可复查证据

`evidence-summary.json`由`Summarize-Traces.ps1`从固定六组自有窗口日志生成，只保留固定标签、哈希、计数、时间及布尔值。无像素模式的0黑点不表示无黑区；首组正常主窗达到16384条上限，前缀尚在缩小时，不能拿它排除新区域缺陷。之后改用12步交替序列，在日志容量内完成两次复核。

| 组别 | 有效黑点 | 同坐标后续非黑 | 记录是否截断 |
| --- | ---: | ---: | --- |
| A请求30ms，像素采样，160步 | 272 | 272（均匹配帧） | 否 |
| 当前主窗请求30ms，12步 | 20 | 20 | 否 |
| A请求100ms，12步 | 20 | 20（均匹配帧） | 否 |
| 当前主窗请求100ms，12步 | 20 | 20 | 否 |

两种12步序列相同，但UI计时器实际远慢于请求间隔，不能称为达到10/30Hz的性能对照。A无像素采样组实际请求间隔P50约312ms、构建到复制P95约386ms；正常主窗100ms组实际间隔P50约1650ms。诊断自身占比约0.4%–3.8%，不把它视为无扰动测量。

像素来自自有HWND有效GDI DC，日志不保存截图、RGB、原始HWND、PID、路径或文件清单；不是DWM最终帧时间。黑到非黑只是采样夹逼，不能宣称连续黑屏持续1–2秒。正常RootPaintReturned不是全窗原子帧。半截标题的具体Region／裁切分支未独立定位，最小化恢复黑块也仍单列。

## 工具与检查

- 新增`ResizeDiagnosticTrace`：默认关闭，最多16384条／64 hooks，每几何最多32像素样本，固定阶段与DTO；只有自有窗口，归属检查后取DC并同线程释放，满额明确截断。
- 新增`ResizeDiagnosticReplay`：12步固定常用／最小交替，30/100ms请求可选，记录实际间隔；不改变绘制策略、不强刷、不录屏或更改系统设置。
- 原型增加可选绘制阶段标记；StageOnePreview仅在明确诊断参数时挂接同一工具。Ready前既有的PerformLayout/Refresh仍在暖机之前，不属于自然缩放证据。
- 六组观察均自行退出；当前主窗合成夹具正常清理。只使用自建数据，不访问个人目录、VSS或原始卷。
- 测试构建0警告0错误；诊断默认关闭时`--live-resize-prototype-tests`两档各199项通过，cleanup_deferred=false、alpha非255为0。这不是视觉通过证明。
- 独立只读审计发现并修补两处诊断异常收尾：Application.Run异常时计时器finally释放；未关闭窗口时不Flush、不用二次错误掩盖原失败。该修补后再次构建0警告；上述199项在该异常收尾修补之前运行，异常分支未做故障注入，不伪称动态覆盖。

复现命令（明确弹出合成诊断窗口，自动完成后关闭）：

```powershell
dotnet tests/bin/Release/net10.0-windows/DiskAtlas.Tests.dll --live-resize-preview canvas --trace-pixels --replay-30
dotnet tests/bin/Release/net10.0-windows/DiskAtlas.Tests.dll --stage-one-preview b --reading-fixture --resize-pixels --replay-100
```

原型可用`--trace`替代`--trace-pixels`，主窗可用`--resize-trace`替代`--resize-pixels`；无明确参数时没有诊断hook或报告。原生主窗日志schema v2使用NativeSizeReturned/RootPaintReturned；旧v1中这两点误名为GeometryAfterChildren/FrameCopied，只能按本记录的真实阶段解释。prototype中原名来自实际源码钩子，语义仍有效。
