# C32 列表滚动背景割裂修复

2026-11-14，Git基线`9ac1f0b`，继承第一阶段未收尾工作区。用户再次反馈列表上下滚动仍割裂、卡顿，明确选择保留背景透出，修复列表合成与滚动。范围见[实施方案](../../docs/ui-list-scroll-repair-plan.md)。用户随后明确反馈“这次滚动正常了”，本项验收通过；不代表第一阶段整体收尾或正式发布。

## 原因与旧证据缺口

原生DataGridView先用`ScrollWindow`搬移行像素，随后才触发`OnScroll`；旧`Invalidate`只排队补画，无法阻止背景先随行移动。`Wallpaper.Paint`还在每个单元格重复执行背景合成。

旧滚动专项只在等待后核对最终WM_PAINT覆盖范围，并通过`VirtualMode`填值，未填充`PopulateGrid`的真实行，因而没有执行主窗名称列自绘。该回调的分类点和文字未完整限制在单元格与脏区交集，文字也未明确保留Graphics裁切。新反例在修改前返回`NameOutsideDirtyClip`，证实这不是只有最终背景重画的问题。

框架依据：[.NET 10滚动源码](https://github.com/dotnet/winforms/blob/v10.0.0/src/System.Windows.Forms/System/Windows/Forms/Controls/DataGridView/DataGridView.Methods.cs)、[ScrollWindow说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-scrollwindow)、[文字裁切标志](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.textformatflags?view=windowsdesktop-10.0)。

## 当前实现

- 列表独立缓存已合成的固定底图，最多400万像素；滚动和选择复用，不按单元格重新取样壁纸。每帧先绘底图，再绘可见行文字、边线和选中覆盖。
- 缓存键覆盖实际影响底图的背景、裁切、窗口／模块尺寸与相对位置、DPI、底色及保护透明度；失效和资源释放另做专项检查。
- 滚轮、原生滚动条、键盘与主窗程序定位采用列表自己的短同步呈现，避免仅等待后续补画；局部暂停重绘严格配对，不对整个主窗口使用。
- 名称列完整保留单元格与脏区交集，文字使用`PreserveGraphicsClipping`。

已确认的1.15倍沿边柔光保持不变。最小化恢复黑块仍按用户决定暂缓，本轮不借此重启相关实验。

## 已有验证与诊断

最终应用／测试均零警告构建。144／96 DPI分别通过：名称裁切各6项、缓存与恢复各36项、原滚动各18项、表面666／664项，完整UI两档18.415／13.264秒通过。真实144 DPI常用窗口已检查向下滚轮、名称选择、PageDown、滚动条拖动和反向快速滚动，背景特征位置稳定、未见文字越界；用户随后亲自确认滚动正常，本项验收通过，不仅凭静态截图关闭问题。

专项覆盖缓存各输入失效、选中色更新但不重建无关底图、400万像素上限、隐藏／显示、嵌套、异常、父窗最小化及外部重绘暂停。隐藏期间有意延迟释放原生暂停，直到显式显示才恢复，避免WM_SETREDRAW(TRUE)强加WS_VISIBLE。父窗仅最小化时则立即解除子列表暂停，不依赖未必出现的VisibleChanged；这仅修复本轮新增事务生命周期，不代表旧黑块解决。主窗选择联动用finally恢复更新守卫，非导航键不启用滚动事务。

固定合成探针使用160条真实`PopulateGrid`行，观察自有列表WM_PAINT及名称回调；每类输入三次，不读取桌面像素。
