# C52：文字缓存一致性与完整UI回归

2026-11-20，用户选择“先修文字缓存和完整回归”，保持现有布局、背景、字号和动效。Git基线仍为`9ac1f0b`；依赖C30暂存及C31–C51未提交的主界面改动，不把这些继承文件混作本轮提交。普通二进制和C51候选均未覆盖，未默认切换DIB或发布。

## 成因与修正

C51保留的缓存/直接文字对比失败，本轮用最小自建控件继续复现。原静态层alpha均为255，改变字体质量和像素格式不能消除差异；在文字绘制前，直接DC读到真实底色`00BFDDFF`，`Graphics.FromImage.GetHdc`读到占位色`000C0B0D`。因此TextRenderer并未在相同的背景像素上计算字边，不是改字号或关闭缓存能够正确解决的问题。

`NativeResizeFrame.RenderOpaque`在选择实际DIB像素的持久源DC上完成不透明层绘制，保存/恢复DC状态，并在GDI文字完成后保留RGB、封好alpha，再交给缓存发布。最多4KiB的封装工作区计入`PixelSurface`预留预算，仍受主窗128MiB总限额约束。绘制失败时丢弃未发布层，走原有直接绘制；停用的DIB会话不反复重建文字缓存。

Treemap文字继续缓存，命中、布局、字号和1.15倍沿边动效不变。普通发布仍走既有GDI+，仅不透明文字缓存源使用真实DC；这不等于默认开启C51的DIB窗口发布功能。
