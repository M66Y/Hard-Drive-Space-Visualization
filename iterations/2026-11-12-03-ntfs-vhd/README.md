# 隔离 VHD 的真实 NTFS 记录比对

日期：2026-11-12；基线：`7985876`。用户明确同意本轮建立 256 MiB 一次性 VHD，经管理员授权挂载，仅在其内部初始化、格式化、生成合成文件并做只读记录比对，随后卸载清理。不是从宿主磁盘划分或格式化现有分区。

## 实现

- `scripts/ntfs-prototype/Invoke-NtfsFixture.ps1`：通过 Unicode `CreateVirtualDisk` API 新建固定大小 VHD；不接受现有磁盘号、盘符或镜像作为参数。镜像反查出的磁盘必须为 FileBackedVirtual、非启动/系统盘、大小匹配、身份稳定；每次初始化、分区及格式化前重新核对。先无盘符格式化，再给格式化完成的分区分配盘符，避免 RAW 卷触发系统格式化提示。
- `NtfsLivePrototype.cs`：仅测试程序集入口。核对工作目录、nonce、卷标记、GUID、VHD 物理路径与卷 extents，再通过卷 GUID 路径创建有限合成文件；读取自身文件身份对应的指定 MFT 记录。原始卷句柄仅有读权限，没有整卷枚举。比较前后再次核对文件身份、大小、链接数和时间，发现变化即失败。
- `NtfsRecordDecoder.cs`：明确区分原始保护记录与内核返回记录。原始入口仍严格校验 USA；内核入口仅接受全体标记或全体已还原保存值的形态，不混用。返回身份/长度先验证，再解码。微软公开接口没有承诺具体 fixup 表示，不能把不匹配一概解释为磁盘损坏。
- 测试与脚本摘要只保留阶段、检查数、固定错误码与清理结果。子进程未退出时不卸载/删除；未确认镜像卸载时不删工作目录。没有原始记录或个人路径进入归档。

## 发现与修正

1. 第一次 DiskPart 镜像创建失败，未挂载；未定位其确切系统原因，改用直接原生 API 后创建成功，避免脚本路径/编码环节。
2. 真实驻留文件的句柄分配大小与原型的“独立数据簇为零”口径不一致，触发失败。非空驻留 DATA 的分配量已改成 `ResidentAllocation` 待补查，逻辑大小仍可用；未以猜测公式消除差异。
3. MFT 名称引用包含独立 DOS 名称属性，不能直接与 Windows 可见硬链接数比较。夹具与校验已改为分别检查原始名称引用和排除 DOS 别名后的可见链接。
4. 分配盘符过早曾出现 Windows 格式化窗口；脚本格式化本身已完成，但记录比对失败后的卸载也会让该窗口失去设备。流程已改为格式化成功后再分配盘符，最终复验通过。

保留四次白名单结果见 `live-attempts.json`，包括失败尝试；每次均确认已卸载/清理。所有原始临时结果文件、镜像、运行日志和测试文件在归档后清理。
