# 个人卷 NTFS 兼容与明确的部分结果

2026-11-13；基线 `00c9b410703237aa14f8555124d2b713668b9a32`。本轮接续 C25，在用户明确允许的个人目录范围内完成真实快照读取、同源逐对象核验和主动取消；没有新建 VHD、读取其他个人范围、打包或发布。

## 问题与取舍

真实范围依次暴露旧入口上限、MFT 属性扩展以及重解析边界。一次 UI 选择返回范围与指定范围不一致，已停止该次操作并排除其验收；后续使用准确的 stdin 范围绑定。中途只有 `ReadFailed` 的报告不足以定位问题，补齐固定阶段、原因和 Windows 数字错误码后，确认最终阻塞为 `IndexBoundary`，不能由此推断硬盘损坏。历史失败没有被改写成成功。

按用户批准的新上限实现固定 `Large` profile 和紧凑路径：最多 1,048,576 个入口、64 Mi UTF-16 名称字符及独立目录路径预算，16,384 个 MFT 页、4,096 个位图扇区；单次原始请求累计最多 1 GiB＋2 MiB、65,536 次、每次最多 64 KiB。Native 补查最多 131,072 对象，8 路、队列 128。旧 Standard 和 VHD 夹具预算不变。

MFT 元信息解析仍保持严格 USA、完整引用/序列、属性实例、VCN 覆盖和物理边界核验；最多 64 KiB 属性列表、64 个扩展记录、1,024 个 run。非首段 DATA 的大小字段不用于最终统计；未支持布局或矛盾不能被补查掩盖。元信息查询只申请属性权限，不申请文件正文读取权限；原始 MFT 页仍可能含邻近记录与驻留片段，沿用本轮明确授权的边界。

普通目录扫描会跳过链接并报告未读全。用户因此批准快扫沿用这一策略：过滤重解析入口，不跟随目标，完整核验保留范围，明确显示“部分快扫完成”和链接未纳入统计。只有这类已声明边界允许部分成功，未知大小、权限或读取错误及身份矛盾仍失败。Wire v3 只传总数和最多 2,000 个父目录身份/名称描述，接收端重建固定原因；详情截断时全部保留目录保守标记未读全。

主窗增加“恢复上次完整结果”，仅保留一个旧完整树及查询上下文。部分结果、随后取消和恢复相互隔离；恢复、新完整结果或关闭释放旧恢复引用。快照结果继续不携带 live USN checkpoint，失败回退在进行中说明原因，未知清理仍阻止后续快扫。

## 验证结果

真实指定范围通过 `personal-ntfs-acceptance-v3` 的 **passed-partial**：保留范围内每个唯一对象的两种大小、身份、硬链接与修改时间和同一快照的独立 Native 查询一致；原始读取预算守卫与清理确认通过。`namespace_complete=false`，排除项及其目标不计入统计，不能称整个目录完整扫描成功。随后在建立快照并读取元信息后主动取消，通过清理确认。

实测目录仅由 stdin 经受认证的生产管道传递，未进入 argv、仓库或公开结果；原始页、个人清单、身份、统计值和逐项差异均未保存。独立全对象审计是额外验收成本，本轮没有个人目录性能基准或 WizTree 速度结论。

应用与测试 Release 构建均零警告。扩展解析与实际 Reader 的内存替身组合 102 项、续段 61、位图 bundle 41、Large 25、链接策略 36、Wire 277、Coordinator 67、管道 45、来源 52、同源审计反例 54＋输入 18 等通过。两档 DPI 主窗各 86 项，包含七项保留流程、部分结果、恢复完整结果、取消与查询恢复；普通 UI 两档、核心/高级/日志增量与旧预算守卫也通过。具体结果见 [checks.json](checks.json)。

可选屏幕截图捕获未得到可用图片，之后用户用 Escape 停止 Computer Use，未再进行窗口控制。本轮真实结果画面仍待人工观察；合成主窗检查和真实后台核验不能替代这一项。Windows 10 新后端、更多格式与个人性能收益仍待验收。

## 健壮性与清理

独立复核了取消/并发、来源关闭、统计/硬链接、重解析边界、协议错误及隐私。修复游标集合长期保留已释放对象，以及清理阶段分配失败可能跳过 VSS 关闭的边界；故障测试确认即使游标释放失败仍尝试清理快照。底层预算被回调净化后仍保留“超限”分类。

纳入本轮验收的真实探针均返回快照清理确认，无活动测试进程。已清理本轮隔离 UI 配置、诊断、合成截图与未接入的 UI 验收辅助文件；历史本机原始失败样本保持忽略且未改动。当前构建保留用于开发，正式 v1.5.0 资产不变。

## 恢复与提交

`files.json` 保存本轮文件清单与 Git 索引字节 SHA-256，不哈希清单或补丁自身；`changes.patch` 为基线上的可恢复变更，包含清单，不包含补丁自身。恢复应使用二进制补丁且关闭换行转换，逐项核对清单；Git 提交保存完整版本。提交/推送状态以该归档所属提交及远程分支为准，不在正文嵌入自引用提交号。
