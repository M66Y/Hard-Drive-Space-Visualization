# C48：DIB缓冲候选，用户确认明显改善

2026-11-15。用户批准[直接像素缓冲方案](../../docs/ui-native-frame-buffer-prototype-plan.md)，实际体验后反馈：**“明显改善，先保留这版候选”**。按此决定保留独立候选，不接入正常版，不宣布连续缩放闪黑彻底解决，也不关闭第一阶段或最小化恢复问题。

## 实现与交付

`NativeResizeFrame`显式拥有顶向下32位DIB及持久内存DC，Bitmap／Graphics包装同一块像素。发布前同步GDI+，从真实DIB直接BitBlt；不再把GDI+临时HDC当作图片源。目标裁切、坐标映射和变换必须符合受限条件，否则保留原回退并记录固定失败码。无限托管裁切不创建HRGN，也不覆盖现有原生裁切。

主窗只在原生size、DPI及状态代际匹配时提前发布准备帧。句柄销毁会释放DIB和别名、清除待发布布局；重新创建的空缓冲必须先完整填充，不能因静态缓存命中而只画沿边柔光。所有权、线程约束、失败释放及frame＋静态缓存128MiB上限保留。布局、背景比例、双行列表、1.15倍沿边柔光均未改。

本机保留入口：`artifacts/resize-candidate-C48/app/AsukaLens.NativeFramePrototype.exe`。不带参数启动A；F6为程序驱动尺寸演示，F2切换原生控件对照。候选使用合成数据，不扫描个人目录。最终候选已重新打开；普通`bin/Release`和正式v1.5.0未替换。

首次用户体验后，仅补充句柄销毁及新缓冲首帧保护并重开，未更改布局和发布技术。首次展示与最终DLL哈希在[构建清单](build-manifest.json)分列，不能把首次反馈冒充对最终生命周期边界的人工验证。

## 窗口诊断与限制

固定12步序列、同代码Bitmap对照与DIB候选均包含新尺寸完整准备。A的DIB最终23次发布全部原生成功、0回退，发布p50约0.85ms、p95约1.1ms；Bitmap实际33次发布，p50约37ms、p95约65ms。真实绘制次数因额外Paint／动画不同，因此只说明该发布路径的局部成本，不能据此换算整窗提速倍数或FPS。

两者11次新尺寸准备总量都约1.46秒，约133ms／次；首帧布局／渲染成本仍在。`PublishEnd`是尝试结束，不等于复制成功；成功须另核native／FrameCopied计数。诊断的Root-WM_PAINT上下文与非Root-WM_PAINT上下文只是消息栈分类，原生组合的后者还包括父背景回调，不冒充全是提前准备帧。

A几何后44个有效根表面取点均匹配新帧且无黑；`NcPaintEntering`仍有20个复制前黑点，返回后的有效点无黑。原生All组合59次发布中33次原生、26次以`TargetOrigin`回退；44个几何后根取点无黑，但只38点匹配预期帧，6点差异待查，不放宽映射守卫换取通过。子窗口覆盖导致的未知根取点保持未知。

这些是自有GDI表面离散观察，不是DWM连续帧证据，不证明鼠标实时拖动或所有原生控件无接缝。请求30ms不等于实际30Hz；真实跨屏DPI、125%、冷启动和最小化恢复也未由本轮验收。`DragFullWindows=false`按用户选择保持，不录屏、不改OBS／系统设置，不访问个人卷、VHD或VSS。
